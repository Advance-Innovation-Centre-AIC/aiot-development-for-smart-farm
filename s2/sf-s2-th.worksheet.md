## 1. ผลลัพธ์การเรียนรู้

- **LO1** พาบอร์ดขึ้นเครือข่ายด้วย Hotspot มือถือ อ่านเลข IP และแยกได้ว่า "ต่อไม่ติด" กับ "ต่อติดแล้วหลุด" ต่างกันอย่างไร
- **LO2** ส่งค่าฟาร์มจริง (อุณหภูมิ ความชื้น ความกด ความเอียง) และค่าจำลองจากลูกบิดออกไปทุก 5 วินาทีเป็น JSON แล้วเห็นบนมือถือ
- **LO3** **เขียนแอปฝั่งโน้ตบุ๊กของตัวเอง** ที่ subscribe หัวข้อของกลุ่ม แสดงตารางสด บันทึก CSV ไปเปิดใน Excel และมีกฎแจ้งเตือนหนึ่งข้อ
- **LO4** ส่งคำสั่งกลับไปสั่งปั๊มบนบอร์ด แล้วอธิบายได้ว่าบอร์ดต้อง "ไม่เชื่อคนส่ง" อย่างไร (เพดานเวลา น้ำในถัง ปุ่มหยุดฉุกเฉิน)

**สกิลเป้าหมาย:** publish / subscribe · ประกอบ JSON และไม่เชื่อ JSON ของคนอื่น · บันทึกข้อมูลเป็นตารางเพื่อวิเคราะห์ต่อ · ออกแบบกฎอัตโนมัติที่ไม่สั่งรัว (cooldown)

**เตือนก่อนเข้าคาบ — งานของผู้สอน**

1. **บอร์ดต่อ Hotspot มือถือของกลุ่ม ไม่ใช่ WiFi ของสถานที่** WiFi ที่ต้อง login ผ่านหน้าเว็บ (captive portal) บอร์ดกดไม่ได้ จะได้ IP แต่ออกเน็ตไม่ได้ · แต่ละกลุ่มตั้งชื่อและรหัส Hotspot เอง (ดูกล่อง "ตั้ง Hotspot" ก่อนกิจกรรม 1) · iPhone เปิด "เพิ่มความเข้ากันได้สูงสุด (Maximize Compatibility)" · Android เลือก 2.4 GHz ถ้ามีให้เลือก · บอร์ดล็อกโหมด WPA2/WPA3 ต่อวงเปิดไม่ได้
2. **broker** บอร์ด `broker.hivemq.com` พอร์ต 1883 · หน้าเว็บ `wss://broker.hivemq.com:8884/mqtt` · แอป Python พอร์ต 1883 · **ตัวสำรอง** `test.mosquitto.org` พอร์ต 1883 และหน้าเว็บ `wss://test.mosquitto.org:8081/mqtt` — ประกาศให้ทุกกลุ่มแก้ `BROKER` (ไฟล์บอร์ดและ `farm_monitor.py`) กับ `BROKER_URL` (`farm_web.html`) พร้อมกัน
3. **ไฟร์วอลล์ของสถานที่สำหรับพอร์ต 1883 และ 8884 ยังไม่เคยทดสอบ** ก่อนเข้าห้องให้บอร์ดหนึ่งตัวต่อ Hotspot รัน `sf2_02` แล้วเปิดหน้ารวม MQTT <https://advance-innovation-centre-aic.github.io/aiot-development-for-smart-farm/s2/app/mqtt_dashboard.html> บนเน็ตของสถานที่ การ์ดขึ้น = ผ่าน · ไม่ขึ้น = ให้โน้ตบุ๊กเกาะ Hotspot เดียวกับบอร์ด
4. **เลขกลุ่ม** แจก `team01`, `team02`, … ห้ามซ้ำ (บอร์ดผู้สอนใช้ `team00` ได้เฉพาะ `sf2_03`) · ไฟล์บอร์ดไม่ยอมรันถ้ายังเป็น `teamXX` · บอร์ดใช้ client_id `bento-farm-<TEAM>` แอปใช้ `farm-app-<TEAM>-<สุ่ม>` จึงไม่เตะกัน · **ถ้ามีคลาสอื่นใช้หัวข้อ `bento-aiot` บน broker เดียวกันพร้อมกัน** หัวข้อ `bento-aiot/team05/...` จะปนกัน ให้แจกเลขกลุ่มชุดที่ไม่ชนกับคลาสนั้นแทน
5. **โน้ตบุ๊ก** ติดตั้ง Python 3.8+ และ `pip install paho-mqtt` ก่อนเข้าห้อง · กลุ่มที่ติดตั้งไม่ได้ใช้ `app/farm_web.html` แทน (ต้องออกเน็ตถึง cdn.jsdelivr.net และพอร์ต 8884 ได้) · **`farm_monitor.py` และ `farm_web.html` ทดสอบกับ broker.hivemq.com จริงแล้ว** โดยใช้บอร์ดจำลองบนโน้ตบุ๊กที่ส่งข้อความแบบเดียวกับ `sf2_02`/`sf2_03`: ตารางและ CSV ครบทุกใบ กฎดินแห้งสั่งปั๊มถึงบอร์ด เว้นช่วง 60 วิ ถูกต้อง ปุ่มบนหน้าเว็บสั่งถึงบอร์ด · **บอร์ดจริง:** ไฟล์บอร์ดรันกับ Wi-Fi และ MQTT จริงบนบอร์ด TESAIoT Dev Kit แล้ว (broker.hivemq.com): ค่าจากบอร์ดถึง `farm_monitor.py` และลง CSV · คำสั่งปั๊มถึงบอร์ด · Gateway สั่ง PLC รดน้ำเองเมื่อดินแห้ง · ยกเว้น `sf2_05` ที่ต้องใช้รหัสอุปกรณ์จากผู้สอน · ในการทดสอบเดียวกัน broker สาธารณะรับการเชื่อมต่อช้าเกิน 10 วินาทีเป็นบางครั้ง ให้ผู้สอนลองหนึ่งรอบก่อนคาบ
6. **ฉายหน้าห้อง** หน้ารวม `app/mqtt_dashboard.html` (ROOT = `bento-aiot`) เห็น telemetry กับ event ของทุกกลุ่ม และมีช่อง JSON สำหรับส่งคำสั่ง เช่น `{"cmd":"ack"}` `{"cmd":"set","t_hi":28}`
7. **Emulator** โปรแกรมบอร์ดรันบน BENTO Emulator ได้และจอทำงาน แต่ `mqtt` ของ Emulator เป็น broker จำลองอยู่ในเบราว์เซอร์ ไม่ต่อ broker จริง (ซอร์ส `bento-emulator/py/mqtt.py` เขียนไว้ว่า "No TCP leaves the browser") ค่าที่บอร์ดใน Emulator ส่งจึงไม่ไปถึง `farm_web.html` หรือ `farm_monitor.py` และคำสั่งจากแอปก็ไม่ถึงบอร์ดใน Emulator — บอร์ดใน Emulator ได้ยินแค่ข้อความที่ตัวเองส่งเข้าหัวข้อที่ตัวเอง subscribe · **หลักฐานข้อ MQTT นับจากบอร์ดจริง**
8. **เสียง** บอร์ดทั้งห้องดังพร้อมกันหนวกหู `sf2_02` มีสวิตช์ `SOUND = False` (ดังเฉพาะตอนกด SW5) ประกาศใช้ถ้าห้องเสียงดังเกิน

## Code Quest — อ่าน · เดา · แก้ · เติม · สร้าง

ทุกกิจกรรมมีโจทย์เป็นขั้น ทำเรียงจากระดับ 1 ขึ้นไป ทำได้ถึงไหนก็ได้แค่นั้น
**โจทย์หลัก (มีเฉลยในคาบ)** = ทุกกลุ่มควรทำให้ได้ มีเฉลยให้เปิดดูได้ในคาบ ไม่มีใครติดค้าง
**โจทย์เพิ่ม (โบนัส เฉลยคาบหน้า)** = ทำเพื่อสนุกและเก็บแต้ม ไม่มีผลต่อเกณฑ์ผ่านคาบ เฉลยต้นคาบ 3

| ระดับ | ทำอะไร | ประเภท | แต้ม |
|---|---|---|---|
| 1 เดา (Predict) | อ่านโค้ด เขียนคำตอบที่เดาไว้ก่อน แล้วรันดูว่าตรงไหม | โจทย์หลัก (มีเฉลยในคาบ) | ข้อละ 1 |
| 2 แก้ (Tweak) | แก้ตัวเลขในส่วน `# ---- 1) ตั้งค่า ----` แล้วดูผล | โจทย์หลัก (มีเฉลยในคาบ) | ข้อละ 2 |
| 3 เติม (Fill-in) | เติมช่อง `____` ในไฟล์ฝึก ให้ผ่านการตรวจอัตโนมัติ | กิจกรรม 4 = โจทย์หลัก (มีเฉลยในคาบ) · กิจกรรม 5 = โจทย์เพิ่ม (โบนัส เฉลยคาบหน้า) | ลงมือทำและจดบันทึก 3 + ผ่านการตรวจ 1 |
| 4 สร้าง (Make) | เพิ่มความสามารถใหม่ 1 อย่างให้ฟาร์มออนไลน์ของกลุ่ม | โจทย์เพิ่ม (โบนัส เฉลยคาบหน้า) | 5 |

> แต้ม Code Quest เป็นแต้มสนุก ไม่นับเกรด · เปิดคำใบ้ท้ายใบงาน 1 ขั้น = −1 แต้ม
> **ระดับ 3 ให้แต้มจากการลงมือ ไม่ใช่จากการทำสำเร็จ:** เขียนคำตอบที่เดาก่อนรัน · ลองอะไรไปบ้าง · ติดตรงไหน — ยังไม่ผ่านก็ได้ 3 แต้ม
> **ไฟล์ฝึกตรวจกฎได้โดยไม่ต้องต่อเน็ต:** รันแล้วมันตรวจก่อนเปิดจอ ผ่านแล้วจึงต่อ WiFi (ต้องแก้ `WIFI_SSID` `WIFI_PASS` `TEAM` ก่อนเหมือนไฟล์ตัวอย่าง)

### ติดขัด? บันไดช่วยเหลือ 5 ขั้น

1. **คำใบ้ 3 ขั้น** ท้ายใบงาน (หัวข้อ "คำใบ้ Code Quest"): ขั้น 1 = แนวคิด · ขั้น 2 = โค้ดครึ่งหนึ่ง · ขั้น 3 = เกือบครบ — เปิดทีละขั้น ขั้นละ −1 แต้ม
2. **อ่านข้อความ error** ด้วยตารางด้านล่าง
3. **ถามเพื่อน 3 คนก่อนถามผู้สอน** (ในทีมหรือทีมข้าง ๆ)
4. **ทางออกฉุกเฉิน:** รันไฟล์ตัวอย่างเต็ม (`s2/sf2_03_remote_pump.py` หรือ `s2/sf2_04_crop_alert.py`) เพื่อไปต่อก่อน แล้วค่อยเปิดดูว่าต่างจากของเราตรงไหน
5. **เฉลย:** โจทย์หลักอยู่ใน [`s2/practise/solutions/`](https://github.com/Advance-Innovation-Centre-AIC/aiot-development-for-smart-farm/blob/main/s2/practise/solutions/sf2_03_practise_solution.py) ตั้งแต่ในคาบ · ทุกข้อ (รวมโจทย์เพิ่ม) อธิบายทีละบรรทัดต้นคาบ 3

   **Android:** ตั้งค่า Hotspot → เลือกคลื่น **2.4 GHz** (ถ้ามีให้เลือก) · ต้องตั้งรหัส บอร์ดต่อวงที่ไม่มีรหัสไม่ได้

### 4.6 ต่อยอด — บอร์ดของเราคือ Smart IoT Gateway (`sf2_06_smart_gateway.py`)

ฟาร์มจริงไม่ได้ต่อสายเซนเซอร์เข้าบอร์ดตรง ๆ: กลางแปลงมี**โหนดเซนเซอร์ไร้สาย**ส่งค่าขึ้น MQTT และที่โรงสูบมี **PLC WiFi** คุมรีเลย์ปั๊ม บอร์ดของเราเป็น **Smart IoT Gateway** อยู่ตรงกลาง: อ่านค่าทุกโหนด ตัดสินใจ สั่ง PLC แล้วโชว์ทุกอย่างบนจอ ส่วนแอปของกลุ่มดูได้ทุกหัวข้อ

```
 [โหนดเซนเซอร์ไร้สาย] --field/soil, field/tank--> [broker] --> [Dev Kit = Smart IoT Gateway: ตัดสินใจ + จอ + เสียง]
                                                              <-- plc/cmd --
 [PLC WiFi -> ปั๊ม]   <--plc/cmd-- [broker] --plc/state--> [Gateway]      [แอปของกลุ่ม: ดูทุกหัวข้อ #]
```

ในห้องเรียนไม่มีโหนดและ PLC จริง: รัน `app/field_sim.py` บนโน้ตบุ๊กเล่นแทน (ดินแห้งลงเอง ปั๊มเดินแล้วดินชื้นขึ้น) หรือให้บอร์ดของอีกกลุ่มรัน `sf2_07_field_station.py` เป็นแปลง (VR1 = ดิน, VR4 = ถัง, ไฟสีฟ้า = รีเลย์) · ตั้ง `TEAM` เดียวกันทุกตัว · หัวข้อและ JSON ทั้งหมดอยู่ใน `app/MQTT_CONTRACT_th.md` ข้อ 0 และ 3.5-3.8

- ☐ Gateway ขึ้นค่าดินและถังจากแปลง · ☐ ดินต่ำกว่า 30 % แล้ว Gateway สั่งรดน้ำเอง ไฟ PLC บนจอติด มีเสียง · ☐ แตะสวิตช์ "ออโต้" ให้ปิด แล้วสั่งเองด้วยปุ่ม SW5
