## 1. ผลลัพธ์การเรียนรู้

- **LO1** พาบอร์ดขึ้นเครือข่ายด้วย Hotspot มือถือ อ่านเลข IP และแยกได้ว่า "ต่อไม่ติด" กับ "ต่อติดแล้วหลุด" ต่างกันอย่างไร
- **LO2** ส่งค่าฟาร์มจริง (อุณหภูมิ ความชื้น ความกด ความเอียง) และค่าจำลองจากลูกบิดออกไปทุก 5 วินาทีเป็น JSON แล้วเห็นบนมือถือ
- **LO3** **เขียนแอปฝั่งโน้ตบุ๊กของตัวเอง** ที่ subscribe หัวข้อของกลุ่ม แสดงตารางสด บันทึก CSV ไปเปิดใน Excel และมีกฎแจ้งเตือนหนึ่งข้อ
- **LO4** ส่งคำสั่งกลับไปสั่งปั๊มบนบอร์ด แล้วอธิบายได้ว่าบอร์ดต้อง "ไม่เชื่อคนส่ง" อย่างไร (เพดานเวลา น้ำในถัง ปุ่มหยุดฉุกเฉิน)

**สกิลเป้าหมาย:** publish / subscribe · ประกอบ JSON และไม่เชื่อ JSON ของคนอื่น · บันทึกข้อมูลเป็นตารางเพื่อวิเคราะห์ต่อ · ออกแบบกฎอัตโนมัติที่ไม่สั่งรัว (cooldown)

**เตือนก่อนเข้าคาบ — งานของผู้สอน**

1. **บอร์ดต่อ Hotspot มือถือของกลุ่ม ไม่ใช่ WiFi ของคณะ** WiFi คณะต้อง login ผ่านหน้าเว็บ (captive portal) บอร์ดกดไม่ได้ จะได้ IP แต่ออกเน็ตไม่ได้ · ให้กลุ่มตั้งชื่อวงเป็นอักษรอังกฤษสั้น ๆ เช่น `bento-team05` รหัสอย่างน้อย 8 ตัว · iPhone เปิด "เพิ่มความเข้ากันได้สูงสุด (Maximize Compatibility)" · Android เลือก 2.4 GHz ถ้ามีให้เลือก · บอร์ดล็อกโหมด WPA2/WPA3 ต่อวงเปิดไม่ได้
2. **broker** บอร์ด `broker.hivemq.com` พอร์ต 1883 · หน้าเว็บ `wss://broker.hivemq.com:8884/mqtt` · แอป Python พอร์ต 1883 · **ตัวสำรอง** `test.mosquitto.org` พอร์ต 1883 และหน้าเว็บ `wss://test.mosquitto.org:8081/mqtt` — ประกาศให้ทุกกลุ่มแก้ `BROKER` (ไฟล์บอร์ดและ `farm_monitor.py`) กับ `BROKER_URL` (`farm_web.html`) พร้อมกัน
3. **ไฟร์วอลล์มหาวิทยาลัยสำหรับพอร์ต 1883 และ 8884 ยังไม่เคยทดสอบ** ก่อนเข้าห้องให้บอร์ดหนึ่งตัวต่อ Hotspot รัน `sf2_02` แล้วเปิดหน้ารวมของคอร์สแม่ <https://advance-innovation-centre-aic.github.io/embedded-systems-for-aiot-developer/examples/web/mqtt_dashboard.html> บนเน็ตมหาวิทยาลัย การ์ดขึ้น = ผ่าน · ไม่ขึ้น = ให้โน้ตบุ๊กเกาะ Hotspot เดียวกับบอร์ด
4. **เลขกลุ่ม** แจก `team01` ถึง `team20` ห้ามซ้ำ (บอร์ดผู้สอนใช้ `team00` ได้เฉพาะ `sf2_03`) · ไฟล์บอร์ดไม่ยอมรันถ้ายังเป็น `teamXX` · บอร์ดใช้ client_id `bento-farm-<TEAM>` แอปใช้ `farm-app-<TEAM>-<สุ่ม>` จึงไม่เตะกัน · **ถ้าคอร์สแม่ (AIoT) เรียนพร้อมกันบน broker เดียวกัน** หัวข้อ `bento-aiot/team05/...` จะปนกัน ให้แจกเลข `team21`–`team40` แทน
5. **โน้ตบุ๊ก** ติดตั้ง Python 3.8+ และ `pip install paho-mqtt` ก่อนเข้าห้อง · กลุ่มที่ติดตั้งไม่ได้ใช้ `app/farm_web.html` แทน (ต้องออกเน็ตถึง cdn.jsdelivr.net และพอร์ต 8884 ได้) · **`farm_monitor.py` และ `farm_web.html` ทดสอบกับ broker.hivemq.com จริงแล้วเมื่อ 28 ก.ย. 2569** โดยใช้บอร์ดจำลองบนโน้ตบุ๊กที่ส่งข้อความแบบเดียวกับ `sf2_02`/`sf2_03`: ตารางและ CSV ครบทุกใบ กฎดินแห้งสั่งปั๊มถึงบอร์ด เว้นช่วง 60 วิ ถูกต้อง ปุ่มบนหน้าเว็บสั่งถึงบอร์ด · **ยังไม่เคยทดสอบกับบอร์ดจริง** ให้ผู้สอนลองหนึ่งรอบก่อนคาบ
6. **ฉายหน้าห้อง** หน้ารวม `mqtt_dashboard.html` ของคอร์สแม่ (ROOT = `bento-aiot`) เห็น telemetry กับ event ของทุกกลุ่ม และมีช่อง JSON สำหรับส่งคำสั่ง เช่น `{"cmd":"ack"}` `{"cmd":"set","t_hi":28}`
7. **Emulator** โปรแกรมบอร์ดรันบน BENTO Emulator ได้และจอทำงาน แต่ `mqtt` ของ Emulator เป็น broker จำลองอยู่ในเบราว์เซอร์ ไม่ต่อ broker จริง (ซอร์ส `bento-emulator/py/mqtt.py` เขียนไว้ว่า "No TCP leaves the browser") ค่าที่บอร์ดใน Emulator ส่งจึงไม่ไปถึง `farm_web.html` หรือ `farm_monitor.py` และคำสั่งจากแอปก็ไม่ถึงบอร์ดใน Emulator — บอร์ดใน Emulator ได้ยินแค่ข้อความที่ตัวเองส่งเข้าหัวข้อที่ตัวเอง subscribe · **หลักฐานข้อ MQTT นับจากบอร์ดจริง**
8. **เสียง** 20 บอร์ดดังพร้อมกันหนวกหู `sf2_02` มีสวิตช์ `SOUND = False` (ดังเฉพาะตอนกด SW4) ประกาศใช้ถ้าห้องเสียงดังเกิน
