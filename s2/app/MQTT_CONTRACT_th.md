# สัญญา MQTT ของฟาร์ม (คาบ 2–3) — ใช้เขียนแอปของกลุ่มเอง

หน้านี้บอกทุกอย่างที่บอร์ดส่งออกมาและทุกคำสั่งที่บอร์ดรับ เขียนแอปเองจากหน้านี้ได้เลย หรือคัดลอกทั้งหน้าไปให้ AI ช่วยเขียนก็ได้ (ดู "ประโยคเริ่มต้น" ท้ายหน้า) ทุกค่าในหน้านี้คัดมาจากโค้ดไฟล์บอร์ด `sf2_02` `sf2_03` `sf2_04` `sf2_06` `sf3_06` `sf3_08` และแปลงจำลองใน `farm_web.html` ไม่ได้เดา — **หน้านี้คือสัญญาตัวจริงตัวเดียว** แอปทุกตัวในคอร์สอ่านจากหน้านี้

## 0. ภาพฟาร์มจริง: บอร์ดของเราคือ Smart IoT Gateway

```
 [โหนดเซนเซอร์ไร้สาย กลางแปลง]                         [PLC WiFi ที่โรงสูบ -> รีเลย์ -> ปั๊ม/วาล์ว]
   ความชื้นดิน, ระดับน้ำในถัง                                ^ plc/cmd            | plc/state
        | field/soil, field/tank                      |                    v
        v                                             |                    |
   ==================================  MQTT broker  ===================================
        |                 ^              |              ^                   |
        v                 | telemetry    v              | cmd               v  (ดูได้ทุกหัวข้อ #)
 [Dev Kit = Smart IoT Gateway]  ตัดสินใจ + จอสัมผัส + เสียง + ไฟ     [แอปของกลุ่ม: เว็บ / มือถือ]
```

- **โหนดเซนเซอร์** ส่งค่าอย่างเดียว ไม่ตัดสินอะไร
- **Gateway (Dev Kit)** อ่านค่าทุกโหนด ตัดสินว่าต้องรดน้ำไหม สั่ง PLC แสดงผลบนจอ และรายงานสรุปให้แอป
- **PLC** ทำตามคำสั่ง แต่มีระบบป้องกันของตัวเอง (เปิดนานเกินไม่ได้ ถังแห้งไม่เปิด) แม้ Gateway สั่งผิดก็ไม่พัง
- **แอปของกลุ่ม** ดูได้ทุกหัวข้อ และสั่งผ่าน Gateway (ไม่สั่ง PLC ตรง) เพื่อให้กฎความปลอดภัยอยู่ที่เดียว
- ในห้องเรียนไม่มีโหนดและ PLC จริง ใช้ **PLC Simulator** ในหน้า `farm_web.html` เล่นแทน (ข้อ 6) หรือให้บอร์ดอีกกลุ่มรัน `sf2_07_field_station.py` เป็นแปลงให้

## 2. หัวข้อ (topic)

`<ทีม>` คือเลขกลุ่ม เช่น `team05` (ตัวเล็กทั้งหมด ต้องตรงกับ `TEAM` ในไฟล์บอร์ด)

| หัวข้อ | ทิศทาง | มีอะไร |
|---|---|---|
| `bento-aiot/<ทีม>/telemetry` | บอร์ด → แอป | ค่าฟาร์มทุก 5 วินาที |
| `bento-aiot/<ทีม>/event` | บอร์ด → แอป | เหตุการณ์ (กดปุ่มเรียก, แจ้งเตือนพืช) |
| `bento-aiot/<ทีม>/cmd` | แอป → บอร์ด | คำสั่ง |
| `bento-aiot/<ทีม>/field/<เซนเซอร์>` | โหนดเซนเซอร์ → Gateway | ค่าจากแปลง 1 ตัวต่อ 1 หัวข้อ ตอนนี้มี `field/soil` กับ `field/tank` (เพิ่มเองได้ เช่น `field/light`) |
| `bento-aiot/<ทีม>/plc/cmd` | Gateway → PLC | สั่งปั๊ม |
| `bento-aiot/<ทีม>/plc/state` | PLC → Gateway | ปั๊มทำอะไรอยู่จริง |
| `bento-aiot/<ทีม>/ai` | บอร์ด → แอป | ผล AI ที่รันบนบอร์ด (`sf3_06` `sf3_08` คาบ 3) ดูข้อ 3.9–3.11 |
| `bento-aiot/<ทีม>/ai/cmd` | แอป → บอร์ด AI | เลือก / หยุด / เดินโมเดล / รับทราบการเตือน ดูข้อ 3.10 และ 3.11 |
| `bento-aiot/<ทีม>/ai/feedback` | แอป → แอป | คนบอกว่าการเตือนถูกหรือผิด (บอร์ดไม่ฟัง) ดูข้อ 3.11 |

อยากเห็นทุกหัวข้อในทีเดียว: subscribe `bento-aiot/<ทีม>/#` · อยากเห็นทุกโหนด: `bento-aiot/<ทีม>/field/+`

## 3. ข้อความจากบอร์ด (ทุกข้อความเป็น JSON object ข้อความเดียว เข้ารหัส UTF-8)

### 3.1 ค่าฟาร์ม จาก `sf2_02` → `telemetry` (ทุก 5 วิ และทุกครั้งที่กด SW5 = ปุ่มล่าง)

```json
{"id": "team05", "n": 12, "temp_c": 27.4, "rh": 63.1, "hpa": 1008.4, "az": 7.71, "soil": 55, "light": 70, "tank": 80, "sim": "soil light tank", "by": "timer"}
```

| คีย์ | ชนิด | หน่วย | ช่วง | ความหมาย |
|---|---|---|---|---|
| `id` | ข้อความ | — | `team01`, `team02`, … | เลขกลุ่มที่ผู้สอนแจก |
| `n` | จำนวนเต็ม | ใบ | 1, 2, 3 … | ลำดับข้อความ เริ่ม 1 ใหม่ทุกครั้งที่รันไฟล์ ใช้ดูว่ามีใบหาย |
| `temp_c` | ทศนิยม 1 ตำแหน่ง หรือ `null` | °C | ราว 15–45 | อุณหภูมิจาก SHT40 บวกค่าชดเชย `TEMP_OFFSET` (บอร์ดอุ่นจากตัวเอง) |
| `rh` | ทศนิยม 1 ตำแหน่ง หรือ `null` | % | 0–100 | ความชื้นอากาศจาก SHT40 |
| `hpa` | ทศนิยม 1 ตำแหน่ง หรือ `null` | hPa | ราว 990–1030 | ความกดอากาศจาก DPS368 |
| `az` | ทศนิยม 2 ตำแหน่ง หรือ `null` | m/s² | −9.8 ถึง 9.8 | แรงโน้มถ่วงแกนตั้งจาก BMI270 วางราบ ≈ 9.8 · บอร์ด Dev Kit วางปกติเอียงอยู่แล้ว ได้ราว 7.7 · ค่าตกลงมาก = "กระถางล้ม" |
| `soil` | จำนวนเต็ม | % | 0–100 | **จำลอง** ความชื้นดินจากลูกบิด VR1 |
| `light` | จำนวนเต็ม | % | 0–100 | **จำลอง** แสงจากลูกบิด VR3 |
| `tank` | จำนวนเต็ม | % | 0–100 | **จำลอง** น้ำในถังจากลูกบิด VR4 |
| `sim` | ข้อความ | — | `"soil light tank"` | บอกว่าคีย์ไหนมาจากลูกบิด ไม่ใช่เซนเซอร์จริง |
| `by` | ข้อความ | — | `"timer"` หรือ `"sw5"` | ส่งเพราะครบ 5 วิ หรือเพราะคนกด SW5 |

`null` = เซนเซอร์ตัวนั้นอ่านไม่ได้รอบนั้น แอปต้องไม่พังเมื่อเจอ `null`

### 3.2 สถานะปั๊ม จาก `sf2_03` → `telemetry` (ทุก 5 วิ)

```json
{"id": "team05", "n": 7, "soil": 20, "tank": 80, "pump": 1, "sim": "soil tank"}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `id`, `n` | เหมือน 3.1 | |
| `soil`, `tank` | จำนวนเต็ม 0–100 % | **จำลอง** จาก VR1 และ VR4 |
| `pump` | 0 หรือ 1 | ปั๊มกำลังเปิดอยู่ไหม (บนบอร์ดคือไฟ RGB สีฟ้า) |
| `sim` | `"soil tank"` | คีย์ที่จำลอง |

ไม่มี `temp_c` ในไฟล์นี้ แอปต้องรับได้ทั้งสองแบบ (ดูว่ามีคีย์ไหนก่อนใช้)

### 3.3 กดปุ่มเรียก จาก `sf2_02` → `event` (ทุกครั้งที่กด SW6 = ปุ่มบน)

```json
{"id": "team05", "event": "sw6", "msg": "call"}
```

### 3.4 แจ้งเตือนพืช จาก `sf2_04` → `event` (เฉพาะตอนระดับเปลี่ยน รอบแรกส่งเสมอ)

```json
{"id": "team05", "crop": "tomato", "level": 2, "alert": "hot", "temp_c": 33.5, "rh": 62.0, "sun_c": 5}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `crop` | `tomato` `lettuce` `mushroom` `orchid` | พืชที่กลุ่มเลือก |
| `level` | 0 / 1 / 2 | 0 = สบาย, 1 = เริ่มเครียด, 2 = แย่แล้ว (บอร์ดร้องเตือนซ้ำจนมีคนรับทราบ) |
| `alert` | ข้อความ | `ok` หรือปัญหาต่อกันด้วย `+` จาก `cold` `hot` `dry` `wet` เช่น `hot+dry` |
| `temp_c` | ทศนิยม 1 ตำแหน่ง °C | อุณหภูมิที่ใช้ตัดสิน **รวมแดดจำลองแล้ว** |
| `rh` | ทศนิยม 1 ตำแหน่ง % | ความชื้นอากาศ |
| `sun_c` | จำนวนเต็ม 0–10 °C | แดดจำลองจาก VR3 ที่บวกเข้าไปใน `temp_c` |

### 3.5 ค่าจากโหนดเซนเซอร์ → `field/<เซนเซอร์>` (ทุก 5 วิ ต่อโหนด)

```json
{"node": "soil-1", "value": 42, "unit": "%", "n": 17}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `node` | ข้อความ | ชื่อโหนด เช่น `soil-1` `tank-1` (แปลงใหญ่มีหลายโหนดได้) |
| `value` | จำนวนเต็ม | ค่าที่วัดได้ · `field/soil` = ความชื้นดิน 0–100 · `field/tank` = น้ำในถัง 0–100 |
| `unit` | ข้อความ | หน่วยของ `value` ตอนนี้เป็น `%` ทั้งคู่ |
| `n` | จำนวนเต็ม | ลำดับข้อความของโหนดนั้น ใช้ดูว่ามีใบหาย |

### 3.6 สถานะปั๊มจาก PLC → `plc/state` (ทุกครั้งที่เปลี่ยน ทุกครั้งที่ได้คำสั่ง และทุก 5 วิ)

```json
{"pump": 1, "left_s": 8, "why": "on", "n": 23}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `pump` | 0 หรือ 1 | ปั๊มเดินอยู่จริงไหม (ความจริงอยู่ที่ PLC ไม่ใช่ที่คนสั่ง) |
| `left_s` | จำนวนเต็ม วินาที | อีกกี่วินาทีปั๊มจะดับเอง (0 = ไม่ได้เดิน) |
| `why` | ข้อความ | `start` เพิ่งเปิด PLC · `on` เปิดตามคำสั่ง · `off` ปิดตามคำสั่ง · `timeout` ครบเวลาดับเอง · `blocked_tank` ไม่ยอมเปิด หรือดับเองระหว่างเดิน เพราะถังต่ำกว่า 10 % · `bad_cmd` คำสั่งอ่านไม่ได้ · `stop` คนกดหยุดฉุกเฉินที่ตัว PLC (`sf2_07` ปุ่ม SW5) · `tick` รายงานตามรอบ |
| `n` | จำนวนเต็ม | ลำดับข้อความ |

ถ้าไม่ได้ยิน `plc/state` เกิน 15 วินาที ให้ถือว่า PLC หลุด

### 3.7 สรุปจาก Gateway (`sf2_06`) → `telemetry` (ทุก 5 วิ)

```json
{"id": "team05", "n": 31, "soil": 42, "tank": 77, "pump": 0, "auto": 1, "by": "gateway"}
```

| คีย์ | ความหมาย |
|---|---|
| `soil`, `tank` | ค่าล่าสุดที่ได้จากโหนด (`null` ถ้ายังไม่เคยได้ยิน หรือเงียบเกิน 15 วิ) |
| `pump` | 0/1 ตาม `plc/state` ล่าสุด (`null` ถ้า PLC เงียบเกิน 15 วิ) |
| `auto` | 1 = Gateway รดน้ำเองเมื่อดินแห้ง · 0 = รอคนสั่ง |
| `by` | `"gateway"` บอกว่าข้อความนี้มาจาก Gateway ไม่ใช่จากโหนด |

### 3.8 เหตุการณ์จาก Gateway (`sf2_06`) → `event`

```json
{"id": "team05", "event": "pump", "pump": 1, "why": "on"}
{"id": "team05", "event": "plc_lost"}
{"id": "team05", "event": "auto_water", "soil": 28}
```

`pump` = ปั๊มเปลี่ยนสถานะตาม PLC (`why` ตาม 3.6) · `plc_lost` = PLC เงียบเกิน 15 วิ · `auto_water` = Gateway ตัดสินใจรดน้ำเองเพราะดินแห้ง

### 3.9 ผล AI บนบอร์ด จาก `sf3_06` → `ai` (คาบ 3)

```json
{"id": "team05", "n": 42, "model": "AnomalousVibration", "label": "anomaly", "conf": 91}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `id` · `n` | ข้อความ · จำนวนเต็ม | เลขกลุ่ม · ลำดับข้อความ เริ่ม 1 ใหม่ทุกครั้งที่รัน |
| `model` | ข้อความ | **ชื่อ**โมเดลที่รันอยู่เท่านั้น ไม่มีรหัสหรือ id ของโมเดล |
| `label` | ข้อความ | ป้ายผลล่าสุดของโมเดล · `"-"` = ยังไม่มีผล · `sf3_06` ถือว่าป้ายชุดนี้อันตราย: `anomaly` `shaking` `sirens` `cough` `baby_cry` `chainsaw` `crackling_fire` `alarm` (ชุดเดียวกับ `sf3_04` ครอบคลุมโมเดลจาก Store และโมเดลในตัว) |
| `conf` | จำนวนเต็ม 0–100 | ความมั่นใจของป้ายนั้น เป็น % |

**ป้ายสลับไปมาได้:** ระหว่างเขย่า โมเดล `AnomalousVibration` ให้ป้ายสลับ `anomaly` ↔ `unlabeled` ทุก 1–2 วินาที (ทดสอบบนบอร์ดจริง) แอปจึงควรเตือนเมื่อ **ป้ายอันตรายอย่างน้อย 3 ใน 5 ข้อความล่าสุด** ไม่ใช่ทุกครั้งที่เห็นป้ายเดียว

**จังหวะการส่ง:** ส่งทันทีเมื่อได้ผลใหม่ที่ป้ายเปลี่ยน · ป้ายไม่เปลี่ยนก็ส่งซ้ำทุก 2 วินาที (heartbeat) · ห่างกันอย่างน้อย 200 ms · QoS 0 ไม่เก็บค้าง (retain) · แอปควรขึ้น "AI เงียบ" เมื่อไม่ได้ยินเกินราว 6 วินาที

### 3.10 บอร์ด AI ที่ตัดสินเตือนเอง → `ai` + `event` และรับคำสั่งทาง `ai/cmd`

ไฟล์บอร์ดที่นับผลเอง (ป้ายอันตรายอย่างน้อย 3 ใน 5 ผลล่าสุด) ใช้ข้อความชุดนี้ต่อยอดจากข้อ 3.9

```json
{"id": "team05", "n": 42, "model": "AnomalousVibration", "label": "anomaly", "conf": 91, "alarm": 1}
{"id": "team05", "event": "ai_alarm_start", "model": "AnomalousVibration", "label": "anomaly", "conf": 91}
```

| ส่วน | หัวข้อ | รายละเอียด |
|---|---|---|
| สถานะ | `ai` | ข้อความเดิมของข้อ 3.9 เพิ่มคีย์ `"alarm"`: `1` = บอร์ดกำลังเตือน · `0` = ปกติ · แอปที่เปิดกลางทางก็รู้ว่ากำลังเตือนอยู่ |
| เริ่ม/หายเตือน | `event` (หัวข้อเดิมของกลุ่ม) | ส่งครั้งเดียวตอนเปลี่ยน: `"event": "ai_alarm_start"` หรือ `"ai_alarm_end"` พร้อม `model` `label` `conf` · ไม่มี `n` เหมือน event อื่น · หน้ารวมของห้องและตัวส่งแจ้งเตือนเข้ามือถือเห็นได้ทันทีเพราะฟังหัวข้อ `event` อยู่แล้ว |
| หยุดโมเดล | `ai` | หลังคำสั่ง `stop` ยังส่งทุก 2 วินาทีด้วย `"model": ""` `"label": "-"` `"conf": 0` แอปจึงเห็นว่า "หยุดอยู่" ไม่ใช่เงียบหาย |
| คำสั่ง | `ai/cmd` | `{"cmd":"select","model":"<ชื่อ>"}` · `{"cmd":"stop"}` · `{"cmd":"run"}` · ยาวไม่เกิน 200 ไบต์ · ชื่อโมเดลต้องตรงกับรายการที่ไฟล์อนุญาตและมีอยู่บนบอร์ด · คำสั่งห่างกันอย่างน้อย 3 วินาที · อย่างอื่นบอร์ดไม่สนใจ |
| ตอบรับ | `ai` | หลังเปลี่ยนโมเดล บอร์ดส่งข้อความสถานะทันที คีย์ `model` คือคำยืนยัน |

ชื่อโมเดลในข้อความเป็น **ชื่อ** เท่านั้น ไม่มีรหัสหรือ id ของโมเดล · แอปในชุด `apps/` มีกฎ "AI alarm เริ่ม (event)" และ "AI alarm ค้างอยู่ (state)" ให้แล้ว

### 3.11 ภารกิจ AI ในฟาร์ม จาก `sf3_08` → `ai` + `event` · คนตอบกลับทาง `ai/feedback` (คาบ 3)

`sf3_08_farm_ai_missions.py` ตัดสินสองทาง: **กฎที่เขียนเอง** กับ **AI** แล้วบอกว่าทั้งสองเห็นตรงกันไหม เลือกภารกิจด้วย `MISSION` บรรทัดเดียว ข้อความสถานะต่อยอดจากข้อ 3.9 และ 3.10 (คีย์เดิมอยู่ครบ แอปที่อ่านข้อ 3.9 ได้ยังอ่านได้)

```json
{"id": "team05", "n": 42, "m": "pump", "model": "AnomalousVibration", "label": "anomaly", "conf": 91, "p2": "unlabeled", "c2": 9, "ms": 12, "rk": "vib", "rule": 1, "rv": 2.31, "rl": 1.5, "agree": "both", "lvl": 2, "alarm": 1}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `id` `n` `model` `label` `conf` | ตามข้อ 3.9 | `id` คือ `team01`–`team99` · `model` คือชื่อที่บอร์ดรายงาน ไม่ใช่ชื่อใน Store (เช่น Store `Siren` = บอร์ด `SirenDetection`) · ใช้ตัวสำรองในตัวอยู่ก็เป็นชื่อตัวนั้น · `"rule-only"` กับ `label` `"-"` `conf` `0` = ภารกิจกำลังทำงานด้วยกฎอย่างเดียวเพราะไม่มีโมเดล (ไม่ใช่หยุด ซึ่งข้อ 3.10 ใช้ `model` `""`) |
| `m` | ข้อความ | ภารกิจ: `pump` `siren` `barn` `night` `voice` `worker` `drill` (ตารางข้างล่าง) |
| `p2` · `c2` | ข้อความ · 0–100 | ป้ายอันดับสองและความมั่นใจ % บอกว่าโมเดลลังเลแค่ไหน · ไม่มี = `"-"` และ `0` |
| `ms` | จำนวนเต็ม | เวลาที่ AI ใช้คิดต่อครั้ง (ms) · ไม่รู้ = `0` |
| `rk` | ข้อความ | ชนิดของกฎ: `vib` ค่าสั่น m/s² · `loud` วินาทีที่เสียงดังต่อเนื่อง · `rate` จำนวนครั้งใน 10 นาที · `dur` วินาทีที่สถานะค้าง · `btn` ยืนยันแล้ว 1/0 (พูดซ้ำใน 3 วิ หรือกด SW6) |
| `rule` | 0 / 1 | กฎบอกว่าเกิดเหตุ |
| `rv` · `rl` | ตัวเลข | ค่าของกฎ และเกณฑ์ (หน่วยตาม `rk`) |
| `agree` | ข้อความ | `both` ทั้งคู่บอกเกิดเหตุ · `ai` AI ฝ่ายเดียว · `rule` กฎฝ่ายเดียว · `none` ไม่มีใครบอก |
| `lvl` | 0 / 1 / 2 | `2` ยืนยันสองทาง (เตือนจริง) · `1` ฝ่ายเดียว (ให้คนไปดู ไม่ดังลั่น) · `0` ปกติ |
| `alarm` | 0 / 1 | ตามข้อ 3.10: `1` = บอร์ดกำลังเตือนและยังไม่มีใครรับทราบ |

**ฝั่ง AI บอกว่าเกิดเหตุ** เมื่อป้ายของภารกิจชนะด้วยความมั่นใจอย่างน้อย 60 % ใน 3 ของ 5 ผลล่าสุด (เหมือนข้อ 3.10) · **`lvl` กับ `alarm` แยกกัน:** `agree` `both` = `lvl` 2 ทุกภารกิจ ส่วน `alarm` เป็น 1 เมื่อบอร์ดตัดสินเตือน (ภารกิจ `worker` เตือนเมื่อคนงานไม่ตอบใน 30 วิ) · หลังรับทราบ บอร์ดจะเตือนใหม่ก็ต่อเมื่อ `lvl` ต่ำกว่า 2 ติดต่อกันอย่างน้อย 10 วิ (กันเตือนซ้ำตอนป้ายสลับไปมา) · หลังคำสั่ง `stop` ฝั่ง AI ปิด (`model` `""`) แต่กฎยังทำงาน `agree` จึงเป็นได้แค่ `rule` หรือ `none` และ `lvl` ไม่เกิน 1 · **จังหวะการส่ง** ทุก 2 วินาที และทันทีที่ `label` `lvl` หรือ `alarm` เปลี่ยน ห่างกันอย่างน้อย 200 ms · ทุกข้อความไม่เกิน 255 ไบต์

| `m` | โมเดล (ตัวสำรองบนบอร์ดที่ยังไม่ได้ deploy และใน Emulator) | ป้ายที่นับเป็นเหตุ | กฎคู่ `rk` | event เพิ่ม |
|---|---|---|---|---|
| `pump` | AnomalousVibration (Motion Detection: `shaking`) | `anomaly` | `vib` ค่าสั่นเกินค่าปกติ × 3 | — |
| `siren` | SirenDetection (Siren Detection) | `sirens` | `loud` ดังต่อเนื่อง ≥ 2 วิ | — |
| `barn` | HomeSounds (Cough Detection: `cough`) | `cough` `water_tap` `baby_cry` | `rate` ไอใน 10 นาที · `dur` ก๊อกเปิด ≥ 30 วิ | — |
| `night` | Environment Sounds (Alarm Detection: `alarm`) | `chainsaw` `crackling_fire` `dog` | `loud` ดังต่อเนื่อง (ช่วงเวลาเฝ้าเป็นงานต่อยอด) | `rain` |
| `voice` | Voice Commands (ไม่มี: ใช้ปุ่มแทนเสียง) | `go` `stop` | `btn` ยืนยัน `go` (พูดซ้ำใน 3 วิ หรือกด SW6) | `voice_cmd` |
| `worker` | HumanActivity (ไม่มี: ใช้ IMU นิ่งอย่างเดียว) | `sitting` `standing` (นิ่ง) | `dur` ไม่ขยับ ≥ เกณฑ์ | `check_in` |
| `drill` | DrillMaterialMic (ไม่มี) · **ผู้สอนสาธิตเท่านั้น** | `wood_out` `plastic_out` | `loud` สว่านเดินอยู่ | `drill_done` |

**event ของภารกิจ** (หัวข้อ `event` ไม่มี `n` เหมือน event อื่น · ส่งครั้งเดียวตอนเกิด):

```json
{"id": "team05", "event": "ai_alarm_start", "m": "pump", "model": "AnomalousVibration", "label": "anomaly", "conf": 91, "lvl": 2}
{"id": "team05", "event": "ai_alarm_end", "m": "pump", "by": "ack"}
{"id": "team05", "event": "rain", "m": "night", "conf": 82}
{"id": "team05", "event": "voice_cmd", "m": "voice", "cmd": "go", "ok": 1, "why": ""}
{"id": "team05", "event": "check_in", "m": "worker", "ok": 0}
{"id": "team05", "event": "drill_done", "m": "drill", "mat": "wood", "holes": 3}
```

- `ai_alarm_end` · `by`: `ack` คนรับทราบ (SW6 หรือ `ai/cmd`) · `clear` เหตุหายไปเอง
- `voice_cmd` · `cmd`: `go` หรือ `stop` · `ok` 1 = ทำตาม (`why` เป็น `""`) · 0 = ไม่ทำ โดย `why` บอกเหตุ: `unconfirmed` ยังไม่ยืนยัน หรือ `gap` สั่งถี่เกิน 3 วิ · คำสั่ง `stop` ไม่ต้องยืนยันและทำทันทีเสมอ (`ok` 1)
- `check_in` · `ok` 1 = คนงานกด SW6 ว่าโอเค · 0 = ไม่ตอบใน 30 วิ (ตามด้วย `ai_alarm_start`)
- `drill_done` · `mat`: `wood` หรือ `plastic` · `holes` จำนวนรูของวัสดุนั้นตั้งแต่เริ่มรัน
- ภารกิจ `voice` บอร์ดทำหน้าที่ Gateway: ส่ง `plc/cmd` ตามข้อ 4.2 (`{"pump":1,"sec":10}` · `{"pump":0}`) ห่างกันอย่างน้อย 3 วิ **ยกเว้นคำสั่งหยุด** ที่ส่งทันทีเสมอ (หยุดซ้ำไม่ส่งซ้ำ) · PLC ยังตรวจถังต่ำเองเสมอ (ข้อ 5.9)

**คำสั่งเพิ่ม** ทาง `ai/cmd`: `{"cmd":"ack"}` = รับทราบการเตือน เหมือนกด SW6 · คำสั่งอื่นตามข้อ 3.10

**คนตอบกลับ** ทาง `ai/feedback` (แอปส่ง บอร์ดไม่ฟัง ใช้ทำ CSV ไปฝึกโมเดลใน BENTO Edge AI Trainer):

```json
{"id": "team05", "n": 42, "m": "pump", "v": "true", "lvl": 2, "agree": "both", "label": "anomaly", "conf": 91}
```

`v`: `true` เหตุจริง · `false` เตือนผิด · `unsure` ไม่แน่ใจ (เป็นข้อความ ไม่ใช่ true/false ของ JSON) · `n` คือเลขข้อความสถานะที่คนตอบถึง · ตอบซ้ำที่ `n` เดิมได้ (เปลี่ยนใจ) แอปนับคำตอบล่าสุดของ `n` นั้นเพียงคำตอบเดียว · **แอปแจ้งเตือนเชื่อ `alarm` และ `lvl` ที่บอร์ดตัดสินก่อน** นับ 3 ใน 5 เองเฉพาะกับบอร์ดที่ไม่ส่ง `alarm` (เช่น `sf3_06`) จะได้ไม่เด้งซ้ำหลายใบต่อเหตุการณ์เดียว

## 4. คำสั่งที่บอร์ดรับ → `cmd` (ส่งเป็นข้อความ JSON)

| ส่งแบบนี้ | ไฟล์ที่ฟัง | บอร์ดทำอะไร |
|---|---|---|
| `{"cmd":"pump","on":1,"sec":10}` | `sf2_03` | เปิดปั๊ม `sec` วินาที (ไม่ใส่ = 10 · สูงสุด 30 · ไม่ใช่จำนวนเต็มบวก = 10) แล้วดับเอง **ไม่ยอมเปิดถ้า `tank` ต่ำกว่า 10 %** |
| `{"cmd":"pump","on":0}` | `sf2_03` | ปิดปั๊มทันที |
| `{"cmd":"led","n":0,"on":1}` / `"on":0` | `sf2_03` | เหมือน pump · `n` อื่นที่ไม่ใช่ 0 ถูกปฏิเสธ |
| `{"cmd":"beep"}` | `sf2_03` `sf2_06` | ลำโพงดังหนึ่งครั้ง "เจ้าของฟาร์มเรียก" |
| `{"cmd":"say","text":"HELLO"}` | `sf2_03` `sf2_06` | ตัววิ่งบนจอไฟ RGB 16x8 · รับเฉพาะอักษรอังกฤษ ตัวเลข เครื่องหมาย (ภาษาไทยถูกตัดทิ้ง) ไม่เกิน 20 ตัว · `sf2_03` ไม่วิ่งระหว่างปั๊มเปิด (`sf2_06` วิ่งได้เสมอ เพราะปั๊มอยู่ที่ PLC) |
| `{"cmd":"ack"}` | `sf2_04` | รับทราบแจ้งเตือน บอร์ดหยุดร้อง (กด SW5 ที่บอร์ดก็ได้ผลเดียวกัน) · `sf2_03` `sf2_06` ตอบแค่ว่าไม่มีแจ้งเตือนให้รับทราบ |
| `{"cmd":"set","t_hi":28}` | `sf2_04` | เปลี่ยนเกณฑ์ "ร้อนไป" เป็นจำนวนเต็มที่มากกว่าเกณฑ์หนาวของพืชและไม่เกิน 45 แล้วตัดสินใหม่ทันที |

ข้อความที่ไม่ใช่ JSON object หรือ `cmd` ที่ไม่รู้จัก บอร์ดไม่ทำอะไร (`sf2_03` `sf2_06` ขึ้นข้อความเตือนบนจอให้ด้วย · `sf2_04` เงียบ)

### 4.1 คำสั่งที่ Gateway (`sf2_06`) รับ → `cmd`

| ส่งแบบนี้ | Gateway ทำอะไร |
|---|---|
| `{"cmd":"pump","on":1,"sec":10}` | ตรวจก่อน (ถังต้องไม่ต่ำกว่า 10 % · เวลาเกิน 30 ตัดเหลือ 30) แล้วส่งต่อให้ PLC ทาง `plc/cmd` |
| `{"cmd":"pump","on":0}` | ส่ง `{"pump":0}` ให้ PLC ทันที |
| `{"cmd":"auto","on":1}` / `"on":0` | เปิด/ปิดโหมดรดน้ำอัตโนมัติของ Gateway |
| `{"cmd":"beep"}` | ลำโพงของ Gateway ดังหนึ่งครั้ง "เจ้าของฟาร์มเรียก!" (ไม่ผ่าน PLC) |
| `{"cmd":"say","text":"HELLO"}` | ตัววิ่งบนจอไฟ RGB ของ Gateway (กติกาเดียวกับ `sf2_03` แต่วิ่งได้แม้ปั๊มเปิด) |

| ส่งแบบนี้ | PLC ทำอะไร |
|---|---|
| `{"pump":1,"sec":10}` | เปิดปั๊ม `sec` วินาที (ไม่ใส่หรือไม่ใช่จำนวนเต็มบวก = 10 · เกิน 30 ตัดเหลือ 30) · ถังต่ำกว่า 10 % ไม่เปิด ตอบ `why: blocked_tank` |
| `{"pump":0}` | ปิดปั๊มทันที |

PLC ตอบด้วย `plc/state` ทุกครั้งที่ได้คำสั่ง

## 5. กติกาที่ต้องรู้

1. **ไม่มี retain** บอร์ดส่งแบบ QoS 0 และไม่เก็บค่าไว้บน broker (ตั้งตายตัวในเฟิร์มแวร์) แอปที่เปิดทีหลังจะเห็นแค่ใบถัดไป ถ้าอยากเห็นย้อนหลังแอปต้องจดเอง
2. **client id ห้ามซ้ำ** บอร์ดใช้ `bento-farm-<ทีม>-<สุ่ม 4 ตัว>` (Gateway `bento-gw-…` · แปลง `bento-field-…` · ตัวท้ายสุ่มใหม่ทุกครั้งที่ต่อ เช่น `bento-farm-team05-1a2b` จึงรันใหม่ทันทีหลังหยุดก็ไม่ชน id ของรอบก่อน · ต่อไม่ติดบอร์ดลองใหม่เองได้ 3 ครั้ง แต่ละครั้งใช้ตัวสุ่มใหม่) · บอร์ด AI ใช้ `bento-ai-<ทีม>-<สุ่ม 4 ตัว>` · แอปต้องต่อท้ายด้วยตัวสุ่มเสมอ เช่น `farm-app-team05-3fa9c1` ถ้าซ้ำ broker จะเตะตัวที่ต่อก่อนหลุด · บอร์ดตัดการเชื่อมต่อเอง (`mqtt.disconnect()`) ทุกครั้งที่โปรแกรมจบหรือถูกหยุด
3. **broker สาธารณะ ใครก็อ่านและสั่งหัวข้อเราได้** ห้ามส่งรหัสผ่านหรือข้อมูลส่วนตัว และแอปต้องตรวจทุกค่าก่อนใช้ (อาจมีคนส่งขยะมา)
4. **อย่าส่งคำสั่งรัว** บอร์ดเช็กกล่องรับทุก 0.1 วินาที และกล่องรับมีช่องเดียว ถ้าคำสั่งที่สองมาถึงก่อนบอร์ดหยิบคำสั่งแรก คำสั่งแรกหายไปเลย ส่งห่างกันอย่างน้อย 1 วินาที และกฎอัตโนมัติ (เช่น ดินแห้งสั่งรดน้ำ) ต้องเว้นอย่างน้อย 60 วินาทีก่อนสั่งซ้ำ
5. **เช็กว่ามีคีย์ก่อนใช้** ไฟล์บอร์ดแต่ละไฟล์ส่งคีย์ไม่เหมือนกัน และค่าอาจเป็น `null`
6. **BENTO Emulator ใช้ทดสอบแอปได้** Emulator ต่อ broker สาธารณะ (`broker.hivemq.com`, `test.mosquitto.org`) จริงผ่าน WebSocket ต่อท้าย client id ด้วย `-emu` และกล่องรับมีช่องเดียวเหมือนบอร์ด · ถ้าต่อไม่ได้ใน 5 วิ Emulator ใช้ broker จำลองแทนและบอกที่คอนโซล (ตอนนั้นข้อความไม่ออกมาถึงแอป) · broker ชื่ออื่นเป็น broker จำลองเสมอ
7. **ข้อความถึงบอร์ดต้องสั้น** บอร์ดรับข้อความได้ไม่เกิน 255 ไบต์และชื่อหัวข้อไม่เกิน 127 ตัว เกินนั้นถูกตัดทิ้ง · client id ของบอร์ดยาวได้ไม่เกิน 31 ตัว
8. **อุปกรณ์ที่ส่งหาบอร์ดต้องเหลื่อมเวลากัน** Gateway ฟังหลายหัวข้อแต่มีกล่องรับช่องเดียว โหนดและ PLC จึงส่งไม่ถี่กว่าทุก 5 วิ และไม่ส่งพร้อมกัน (PLC Simulator ใน `farm_web.html` เหลื่อมไว้ 0 / 1 / 2 วิ) · Gateway ต้องทนข้อความหายได้ เพราะใบถัดไปมาใน 5 วิ
9. **ความปลอดภัยอยู่หลายชั้น** Gateway ตรวจคำสั่งก่อนส่ง และ PLC ตรวจซ้ำด้วยกฎของตัวเอง ชั้นไหนพลาด อีกชั้นยังกันไว้ได้

## 7. ประโยคเริ่มต้นสำหรับสั่ง AI (คัดลอกหน้านี้ทั้งหน้าไปวางก่อน แล้วตามด้วยประโยคข้างล่าง)

**ก. หน้าเว็บไฟล์เดียว**
> เขียนหน้าเว็บ dashboard ไฟล์ HTML ไฟล์เดียว ใช้ mqtt.js จาก CDN ต่อ `wss://broker.hivemq.com:8884/mqtt` subscribe `bento-aiot/team05/#` ตามสัญญาข้างบน แสดงการ์ดอุณหภูมิ ความชื้น ดิน ถังน้ำ กราฟอุณหภูมิย้อนหลัง 5 นาที รายการ event ล่าสุด และปุ่ม "รดน้ำ 10 วินาที" ที่ส่ง `{"cmd":"pump","on":1,"sec":10}` ไป `bento-aiot/team05/cmd` ใช้ client id สุ่ม รองรับค่า null และคีย์ที่ขาดหาย ใช้ textContent ห้ามใช้ innerHTML กับข้อมูลที่รับมา ภาษาไทยทั้งหน้า ใช้บนมือถือได้

**ข. หน้าเว็บจดข้อมูลและเตือน**
> เขียนหน้าเว็บไฟล์ HTML ไฟล์เดียว ใช้ mqtt.js จาก CDN ต่อ `wss://broker.hivemq.com:8884/mqtt` subscribe telemetry และ event ของ `team05` ตามสัญญาข้างบน จดทุกข้อความเป็นตาราง มีปุ่มดาวน์โหลด CSV ที่เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน (ใส่ BOM ไว้หน้าไฟล์) และเตือนบนจอพร้อมเสียงเมื่อได้ event ที่ `level` เป็น 2 หรือเมื่อ `soil` ต่ำกว่า 30 · ถ้าดินแห้งให้ส่งคำสั่งรดน้ำ แต่เว้นอย่างน้อย 60 วินาทีก่อนสั่งซ้ำ และไม่สั่งเมื่อ `pump` เป็น 1 อยู่แล้ว · ใช้ textContent ห้ามใช้ innerHTML กับข้อมูลที่รับมา

**ค. หน้าเว็บกราฟสด**
> เขียนหน้าเว็บไฟล์ HTML ไฟล์เดียว ใช้ mqtt.js และ Chart.js จาก CDN รับ `bento-aiot/team05/telemetry` ตามสัญญาข้างบน เก็บค่าล่าสุด 300 ใบ แสดงตัวเลขล่าสุดเป็นการ์ดใหญ่ กราฟ temp_c และ soil ย้อนหลัง และปุ่มส่งคำสั่งเปิด/ปิดปั๊มไป `bento-aiot/team05/cmd` ห่างกันอย่างน้อย 1 วินาที ใช้บนมือถือได้

**ง. Node-RED**
> อธิบายทีละขั้นให้สร้าง flow ใน Node-RED ที่ใช้ mqtt in ต่อ `broker.hivemq.com:1883` topic `bento-aiot/team05/telemetry` แปลง JSON แล้วแสดง gauge ความชื้นดินและกราฟอุณหภูมิบน Dashboard พร้อมปุ่มที่ส่ง `{"cmd":"pump","on":1,"sec":10}` ผ่าน mqtt out ไป `bento-aiot/team05/cmd` ตามสัญญาข้างบน และให้ไฟล์ flow JSON ที่ import ได้

**จ. แอปภารกิจ AI (ความเห็นที่สอง)**
> เขียนหน้าเว็บไฟล์เดียว ใช้ mqtt.js จาก CDN ต่อ `wss://broker.hivemq.com:8884/mqtt` subscribe `bento-aiot/team05/ai` และ `bento-aiot/team05/event` ตามสัญญาข้อ 3.11 แสดงการ์ดภารกิจตาม `m` ผล AI (`label` `conf` และอันดับสอง `p2` `c2`) คู่กับผลของกฎ (`rv` เทียบ `rl`) และป้ายระดับ `lvl` 0/1/2 เตือนด้วยเสียงและ Notification เมื่อ `alarm` เปลี่ยนเป็น 1 · ทุกการเตือนมีปุ่ม "เหตุจริง / เตือนผิด / ไม่แน่ใจ" ที่ส่ง `ai/feedback` และปุ่มรับทราบที่ส่ง `{"cmd":"ack"}` ไป `ai/cmd` · ขึ้น "AI เงียบ" สีเทาเมื่อไม่ได้ยินเกิน 6 วินาที · มีปุ่มดาวน์โหลด CSV ของผลตอบกลับ ใช้ textContent ห้ามใช้ innerHTML กับข้อมูลที่รับมา ภาษาไทยทั้งหน้า ใช้บนมือถือได้
