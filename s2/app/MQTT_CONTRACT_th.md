# สัญญา MQTT ของฟาร์ม (คาบ 2–3) — ใช้เขียนแอปของกลุ่มเอง

หน้านี้บอกทุกอย่างที่บอร์ดส่งออกมาและทุกคำสั่งที่บอร์ดรับ เขียนแอปเองจากหน้านี้ได้เลย หรือคัดลอกทั้งหน้าไปให้ AI ช่วยเขียนก็ได้ (ดู "ประโยคเริ่มต้น" ท้ายหน้า) ทุกค่าในหน้านี้คัดมาจากโค้ดไฟล์บอร์ด `sf2_02` `sf2_03` `sf2_04` `sf2_06` `sf3_06` และ `app/field_sim.py` ไม่ได้เดา — **หน้านี้คือสัญญาตัวจริงตัวเดียว** แอปทุกตัวในคอร์สอ่านจากหน้านี้

## 0. ภาพฟาร์มจริง: บอร์ดของเราคือ Smart IoT Gateway

```
 [โหนดเซนเซอร์ไร้สาย กลางแปลง]                         [PLC WiFi ที่โรงสูบ -> รีเลย์ -> ปั๊ม/วาล์ว]
   ความชื้นดิน, ระดับน้ำในถัง                                ^ plc/cmd            | plc/state
        | field/soil, field/tank                      |                    v
        v                                             |                    |
   ==================================  MQTT broker  ===================================
        |                 ^              |              ^                   |
        v                 | telemetry    v              | cmd               v  (ดูได้ทุกหัวข้อ #)
 [Dev Kit = Smart IoT Gateway]  ตัดสินใจ + จอสัมผัส + เสียง + ไฟ     [แอปของกลุ่ม: เว็บ / มือถือ / Python]
```

- **โหนดเซนเซอร์** ส่งค่าอย่างเดียว ไม่ตัดสินอะไร
- **Gateway (Dev Kit)** อ่านค่าทุกโหนด ตัดสินว่าต้องรดน้ำไหม สั่ง PLC แสดงผลบนจอ และรายงานสรุปให้แอป
- **PLC** ทำตามคำสั่ง แต่มีระบบป้องกันของตัวเอง (เปิดนานเกินไม่ได้ ถังแห้งไม่เปิด) แม้ Gateway สั่งผิดก็ไม่พัง
- **แอปของกลุ่ม** ดูได้ทุกหัวข้อ และสั่งผ่าน Gateway (ไม่สั่ง PLC ตรง) เพื่อให้กฎความปลอดภัยอยู่ที่เดียว
- ในห้องเรียนไม่มีโหนดและ PLC จริง ใช้ `app/field_sim.py` เล่นแทน หรือให้บอร์ดอีกกลุ่มรัน `sf2_07_field_station.py` เป็นแปลงให้

## 2. หัวข้อ (topic)

`<ทีม>` คือเลขกลุ่ม เช่น `team05` (ตัวเล็กทั้งหมด ต้องตรงกับ `TEAM` ในไฟล์บอร์ด)

| หัวข้อ | ทิศทาง | มีอะไร |
|---|---|---|
| `bento-aiot/<ทีม>/telemetry` | บอร์ด → แอป | ค่าฟาร์มทุก 5 วินาที |
| `bento-aiot/<ทีม>/event` | บอร์ด → แอป | เหตุการณ์ (กดปุ่มเรียก, แจ้งเตือนพืช) |
| `bento-aiot/<ทีม>/cmd` | แอป → บอร์ด | คำสั่ง |
| `bento-aiot/<ทีม>/field/<เซนเซอร์>` | โหนดเซนเซอร์ → Gateway | ค่าจากแปลง 1 ตัวต่อ 1 หัวข้อ ตอนนี้มี `field/soil` กับ `field/tank` (เพิ่มเองได้ เช่น `field/light`) |
| `bento-aiot/<ทีม>/plc/cmd` | Gateway → PLC | สั่งปั๊ม |
| `bento-aiot/<ทีม>/plc/state` | PLC → Gateway | ปั๊มทำอะไรอยู่จริง |
| `bento-aiot/<ทีม>/ai` | บอร์ด → แอป | ผล AI ที่รันบนบอร์ด (`sf3_06` คาบ 3) ดูข้อ 3.9 |

อยากเห็นทุกหัวข้อในทีเดียว: subscribe `bento-aiot/<ทีม>/#` · อยากเห็นทุกโหนด: `bento-aiot/<ทีม>/field/+`

## 3. ข้อความจากบอร์ด (ทุกข้อความเป็น JSON object ข้อความเดียว เข้ารหัส UTF-8)

### 3.1 ค่าฟาร์ม จาก `sf2_02` → `telemetry` (ทุก 5 วิ และทุกครั้งที่กด SW5 = ปุ่มล่าง)

```json
{"id": "team05", "n": 12, "temp_c": 27.4, "rh": 63.1, "hpa": 1008.4, "az": 7.71, "soil": 55, "light": 70, "tank": 80, "sim": "soil light tank", "by": "timer"}
```

| คีย์ | ชนิด | หน่วย | ช่วง | ความหมาย |
|---|---|---|---|---|
| `id` | ข้อความ | — | `team01`, `team02`, … | เลขกลุ่มที่ผู้สอนแจก |
| `n` | จำนวนเต็ม | ใบ | 1, 2, 3 … | ลำดับข้อความ เริ่ม 1 ใหม่ทุกครั้งที่รันไฟล์ ใช้ดูว่ามีใบหาย |
| `temp_c` | ทศนิยม 1 ตำแหน่ง หรือ `null` | °C | ราว 15–45 | อุณหภูมิจาก SHT40 บวกค่าชดเชย `TEMP_OFFSET` (บอร์ดอุ่นจากตัวเอง) |
| `rh` | ทศนิยม 1 ตำแหน่ง หรือ `null` | % | 0–100 | ความชื้นอากาศจาก SHT40 |
| `hpa` | ทศนิยม 1 ตำแหน่ง หรือ `null` | hPa | ราว 990–1030 | ความกดอากาศจาก DPS368 |
| `az` | ทศนิยม 2 ตำแหน่ง หรือ `null` | m/s² | −9.8 ถึง 9.8 | แรงโน้มถ่วงแกนตั้งจาก BMI270 วางราบ ≈ 9.8 · บอร์ด Dev Kit วางปกติเอียงอยู่แล้ว ได้ราว 7.7 · ค่าตกลงมาก = "กระถางล้ม" |
| `soil` | จำนวนเต็ม | % | 0–100 | **จำลอง** ความชื้นดินจากลูกบิด VR1 |
| `light` | จำนวนเต็ม | % | 0–100 | **จำลอง** แสงจากลูกบิด VR3 |
| `tank` | จำนวนเต็ม | % | 0–100 | **จำลอง** น้ำในถังจากลูกบิด VR4 |
| `sim` | ข้อความ | — | `"soil light tank"` | บอกว่าคีย์ไหนมาจากลูกบิด ไม่ใช่เซนเซอร์จริง |
| `by` | ข้อความ | — | `"timer"` หรือ `"sw5"` | ส่งเพราะครบ 5 วิ หรือเพราะคนกด SW5 |

`null` = เซนเซอร์ตัวนั้นอ่านไม่ได้รอบนั้น แอปต้องไม่พังเมื่อเจอ `null`

### 3.2 สถานะปั๊ม จาก `sf2_03` → `telemetry` (ทุก 5 วิ)

```json
{"id": "team05", "n": 7, "soil": 20, "tank": 80, "pump": 1, "sim": "soil tank"}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `id`, `n` | เหมือน 3.1 | |
| `soil`, `tank` | จำนวนเต็ม 0–100 % | **จำลอง** จาก VR1 และ VR4 |
| `pump` | 0 หรือ 1 | ปั๊มกำลังเปิดอยู่ไหม (บนบอร์ดคือไฟ RGB สีฟ้า) |
| `sim` | `"soil tank"` | คีย์ที่จำลอง |

ไม่มี `temp_c` ในไฟล์นี้ แอปต้องรับได้ทั้งสองแบบ (ดูว่ามีคีย์ไหนก่อนใช้)

### 3.3 กดปุ่มเรียก จาก `sf2_02` → `event` (ทุกครั้งที่กด SW6 = ปุ่มบน)

```json
{"id": "team05", "event": "sw6", "msg": "call"}
```

### 3.4 แจ้งเตือนพืช จาก `sf2_04` → `event` (เฉพาะตอนระดับเปลี่ยน รอบแรกส่งเสมอ)

```json
{"id": "team05", "crop": "tomato", "level": 2, "alert": "hot", "temp_c": 33.5, "rh": 62.0, "sun_c": 5}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `crop` | `tomato` `lettuce` `mushroom` `orchid` | พืชที่กลุ่มเลือก |
| `level` | 0 / 1 / 2 | 0 = สบาย, 1 = เริ่มเครียด, 2 = แย่แล้ว (บอร์ดร้องเตือนซ้ำจนมีคนรับทราบ) |
| `alert` | ข้อความ | `ok` หรือปัญหาต่อกันด้วย `+` จาก `cold` `hot` `dry` `wet` เช่น `hot+dry` |
| `temp_c` | ทศนิยม 1 ตำแหน่ง °C | อุณหภูมิที่ใช้ตัดสิน **รวมแดดจำลองแล้ว** |
| `rh` | ทศนิยม 1 ตำแหน่ง % | ความชื้นอากาศ |
| `sun_c` | จำนวนเต็ม 0–10 °C | แดดจำลองจาก VR3 ที่บวกเข้าไปใน `temp_c` |

### 3.5 ค่าจากโหนดเซนเซอร์ → `field/<เซนเซอร์>` (ทุก 5 วิ ต่อโหนด)

```json
{"node": "soil-1", "value": 42, "unit": "%", "n": 17}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `node` | ข้อความ | ชื่อโหนด เช่น `soil-1` `tank-1` (แปลงใหญ่มีหลายโหนดได้) |
| `value` | จำนวนเต็ม | ค่าที่วัดได้ · `field/soil` = ความชื้นดิน 0–100 · `field/tank` = น้ำในถัง 0–100 |
| `unit` | ข้อความ | หน่วยของ `value` ตอนนี้เป็น `%` ทั้งคู่ |
| `n` | จำนวนเต็ม | ลำดับข้อความของโหนดนั้น ใช้ดูว่ามีใบหาย |

### 3.6 สถานะปั๊มจาก PLC → `plc/state` (ทุกครั้งที่เปลี่ยน ทุกครั้งที่ได้คำสั่ง และทุก 5 วิ)

```json
{"pump": 1, "left_s": 8, "why": "on", "n": 23}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `pump` | 0 หรือ 1 | ปั๊มเดินอยู่จริงไหม (ความจริงอยู่ที่ PLC ไม่ใช่ที่คนสั่ง) |
| `left_s` | จำนวนเต็ม วินาที | อีกกี่วินาทีปั๊มจะดับเอง (0 = ไม่ได้เดิน) |
| `why` | ข้อความ | `start` เพิ่งเปิด PLC · `on` เปิดตามคำสั่ง · `off` ปิดตามคำสั่ง · `timeout` ครบเวลาดับเอง · `blocked_tank` ไม่ยอมเปิด หรือดับเองระหว่างเดิน เพราะถังต่ำกว่า 10 % · `bad_cmd` คำสั่งอ่านไม่ได้ · `stop` คนกดหยุดฉุกเฉินที่ตัว PLC (`sf2_07` ปุ่ม SW5) · `tick` รายงานตามรอบ |
| `n` | จำนวนเต็ม | ลำดับข้อความ |

ถ้าไม่ได้ยิน `plc/state` เกิน 15 วินาที ให้ถือว่า PLC หลุด

### 3.7 สรุปจาก Gateway (`sf2_06`) → `telemetry` (ทุก 5 วิ)

```json
{"id": "team05", "n": 31, "soil": 42, "tank": 77, "pump": 0, "auto": 1, "by": "gateway"}
```

| คีย์ | ความหมาย |
|---|---|
| `soil`, `tank` | ค่าล่าสุดที่ได้จากโหนด (`null` ถ้ายังไม่เคยได้ยิน หรือเงียบเกิน 15 วิ) |
| `pump` | 0/1 ตาม `plc/state` ล่าสุด (`null` ถ้า PLC เงียบเกิน 15 วิ) |
| `auto` | 1 = Gateway รดน้ำเองเมื่อดินแห้ง · 0 = รอคนสั่ง |
| `by` | `"gateway"` บอกว่าข้อความนี้มาจาก Gateway ไม่ใช่จากโหนด |

### 3.8 เหตุการณ์จาก Gateway (`sf2_06`) → `event`

```json
{"id": "team05", "event": "pump", "pump": 1, "why": "on"}
{"id": "team05", "event": "plc_lost"}
{"id": "team05", "event": "auto_water", "soil": 28}
```

`pump` = ปั๊มเปลี่ยนสถานะตาม PLC (`why` ตาม 3.6) · `plc_lost` = PLC เงียบเกิน 15 วิ · `auto_water` = Gateway ตัดสินใจรดน้ำเองเพราะดินแห้ง

### 3.9 ผล AI บนบอร์ด จาก `sf3_06` → `ai` (คาบ 3)

```json
{"id": "team05", "n": 42, "model": "AnomalousVibration", "label": "anomaly", "conf": 91}
```

| คีย์ | ชนิด | ความหมาย |
|---|---|---|
| `id` · `n` | ข้อความ · จำนวนเต็ม | เลขกลุ่ม · ลำดับข้อความ เริ่ม 1 ใหม่ทุกครั้งที่รัน |
| `model` | ข้อความ | **ชื่อ**โมเดลที่รันอยู่เท่านั้น ไม่มีรหัสหรือ id ของโมเดล |
| `label` | ข้อความ | ป้ายผลล่าสุดของโมเดล · `"-"` = ยังไม่มีผล · `sf3_06` ถือว่า `anomaly` และ `shaking` อันตราย |
| `conf` | จำนวนเต็ม 0–100 | ความมั่นใจของป้ายนั้น เป็น % |

**จังหวะการส่ง:** ส่งทันทีเมื่อได้ผลใหม่ที่ป้ายเปลี่ยน · ป้ายไม่เปลี่ยนก็ส่งซ้ำทุก 2 วินาที (heartbeat) · ห่างกันอย่างน้อย 200 ms · QoS 0 ไม่เก็บค้าง (retain) · แอปควรขึ้น "AI เงียบ" เมื่อไม่ได้ยินเกินราว 6 วินาที

## 4. คำสั่งที่บอร์ดรับ → `cmd` (ส่งเป็นข้อความ JSON)

| ส่งแบบนี้ | ไฟล์ที่ฟัง | บอร์ดทำอะไร |
|---|---|---|
| `{"cmd":"pump","on":1,"sec":10}` | `sf2_03` | เปิดปั๊ม `sec` วินาที (ไม่ใส่ = 10 · สูงสุด 30 · ไม่ใช่จำนวนเต็มบวก = 10) แล้วดับเอง **ไม่ยอมเปิดถ้า `tank` ต่ำกว่า 10 %** |
| `{"cmd":"pump","on":0}` | `sf2_03` | ปิดปั๊มทันที |
| `{"cmd":"led","n":0,"on":1}` / `"on":0` | `sf2_03` | เหมือน pump · `n` อื่นที่ไม่ใช่ 0 ถูกปฏิเสธ |
| `{"cmd":"beep"}` | `sf2_03` | ลำโพงดังหนึ่งครั้ง "เจ้าของฟาร์มเรียก" |
| `{"cmd":"say","text":"HELLO"}` | `sf2_03` | ตัววิ่งบนจอไฟ RGB 16x8 · รับเฉพาะอักษรอังกฤษ ตัวเลข เครื่องหมาย (ภาษาไทยถูกตัดทิ้ง) ไม่เกิน 20 ตัว · ไม่วิ่งระหว่างปั๊มเปิด |
| `{"cmd":"ack"}` | `sf2_04` | รับทราบแจ้งเตือน บอร์ดหยุดร้อง (กด SW5 ที่บอร์ดก็ได้ผลเดียวกัน) · `sf2_03` ตอบแค่ว่าไม่มีแจ้งเตือนให้รับทราบ |
| `{"cmd":"set","t_hi":28}` | `sf2_04` | เปลี่ยนเกณฑ์ "ร้อนไป" เป็นจำนวนเต็มที่มากกว่าเกณฑ์หนาวของพืชและไม่เกิน 45 แล้วตัดสินใหม่ทันที |

ข้อความที่ไม่ใช่ JSON object หรือ `cmd` ที่ไม่รู้จัก บอร์ดไม่ทำอะไร (`sf2_03` `sf2_06` ขึ้นข้อความเตือนบนจอให้ด้วย · `sf2_04` เงียบ)

### 4.1 คำสั่งที่ Gateway (`sf2_06`) รับ → `cmd`

| ส่งแบบนี้ | Gateway ทำอะไร |
|---|---|
| `{"cmd":"pump","on":1,"sec":10}` | ตรวจก่อน (ถังต้องไม่ต่ำกว่า 10 % · เวลาเกิน 30 ตัดเหลือ 30) แล้วส่งต่อให้ PLC ทาง `plc/cmd` |
| `{"cmd":"pump","on":0}` | ส่ง `{"pump":0}` ให้ PLC ทันที |
| `{"cmd":"auto","on":1}` / `"on":0` | เปิด/ปิดโหมดรดน้ำอัตโนมัติของ Gateway |

### 4.2 คำสั่งถึง PLC → `plc/cmd` (Gateway เป็นคนส่ง แอปไม่ควรส่งตรง)

| ส่งแบบนี้ | PLC ทำอะไร |
|---|---|
| `{"pump":1,"sec":10}` | เปิดปั๊ม `sec` วินาที (ไม่ใส่หรือไม่ใช่จำนวนเต็มบวก = 10 · เกิน 30 ตัดเหลือ 30) · ถังต่ำกว่า 10 % ไม่เปิด ตอบ `why: blocked_tank` |
| `{"pump":0}` | ปิดปั๊มทันที |

PLC ตอบด้วย `plc/state` ทุกครั้งที่ได้คำสั่ง

## 5. กติกาที่ต้องรู้

1. **ไม่มี retain** บอร์ดส่งแบบ QoS 0 และไม่เก็บค่าไว้บน broker (ตั้งตายตัวในเฟิร์มแวร์) แอปที่เปิดทีหลังจะเห็นแค่ใบถัดไป ถ้าอยากเห็นย้อนหลังแอปต้องจดเอง
2. **client id ห้ามซ้ำ** บอร์ดใช้ `bento-farm-<ทีม>` แอปต้องต่อท้ายด้วยตัวสุ่มเสมอ เช่น `farm-app-team05-3fa9c1` ถ้าซ้ำ broker จะเตะตัวที่ต่อก่อนหลุด
3. **broker สาธารณะ ใครก็อ่านและสั่งหัวข้อเราได้** ห้ามส่งรหัสผ่านหรือข้อมูลส่วนตัว และแอปต้องตรวจทุกค่าก่อนใช้ (อาจมีคนส่งขยะมา)
4. **อย่าส่งคำสั่งรัว** บอร์ดเช็กกล่องรับทุก 0.1 วินาที และกล่องรับมีช่องเดียว ถ้าคำสั่งที่สองมาถึงก่อนบอร์ดหยิบคำสั่งแรก คำสั่งแรกหายไปเลย ส่งห่างกันอย่างน้อย 1 วินาที และกฎอัตโนมัติ (เช่น ดินแห้งสั่งรดน้ำ) ต้องเว้นอย่างน้อย 60 วินาทีก่อนสั่งซ้ำ
5. **เช็กว่ามีคีย์ก่อนใช้** ไฟล์บอร์ดแต่ละไฟล์ส่งคีย์ไม่เหมือนกัน และค่าอาจเป็น `null`
6. **BENTO Emulator ใช้ทดสอบแอปไม่ได้** MQTT ของ Emulator เป็น broker จำลองในเบราว์เซอร์ ข้อความไม่ออกมาถึงแอป
7. **ข้อความถึงบอร์ดต้องสั้น** บอร์ดรับข้อความได้ไม่เกิน 255 ไบต์และชื่อหัวข้อไม่เกิน 127 ตัว เกินนั้นถูกตัดทิ้ง · client id ของบอร์ดยาวได้ไม่เกิน 31 ตัว
8. **อุปกรณ์ที่ส่งหาบอร์ดต้องเหลื่อมเวลากัน** Gateway ฟังหลายหัวข้อแต่มีกล่องรับช่องเดียว โหนดและ PLC จึงส่งไม่ถี่กว่าทุก 5 วิ และไม่ส่งพร้อมกัน (`field_sim.py` เหลื่อมไว้ 0 / 1.25 / 2.5 วิ) · Gateway ต้องทนข้อความหายได้ เพราะใบถัดไปมาใน 5 วิ
9. **ความปลอดภัยอยู่หลายชั้น** Gateway ตรวจคำสั่งก่อนส่ง และ PLC ตรวจซ้ำด้วยกฎของตัวเอง ชั้นไหนพลาด อีกชั้นยังกันไว้ได้

## 6. ทดสอบโดยไม่มีบอร์ด

รัน `fake_board.py` (อยู่โฟลเดอร์เดียวกับหน้านี้) บนโน้ตบุ๊ก ตั้ง `TEAM` ให้ตรงกับแอป มันส่งข้อความหน้าตาเดียวกับบอร์ดทุกคีย์: 20 วิแรกแบบ `sf2_02` (ดินชื้น) + กด SW6 หนึ่งครั้ง จากนั้นแบบ `sf2_03` (ดินแห้ง 20 %) และแจ้งเตือนพืช 1 ใบที่วินาทีที่ 40 · มันรับคำสั่งด้วยกฎเดียวกับ `sf2_03` แล้วพิมพ์บอกว่าบอร์ดจริงจะทำอะไร

```
pip install paho-mqtt
python fake_board.py
```

ใช้เลขทีมที่ไม่มีใครใช้ (เช่น `team99`) และอย่ารันพร้อมบอร์ดจริงเลขเดียวกัน

**แปลงผักจำลอง (โหนดเซนเซอร์ + PLC):** รัน `field_sim.py` ตั้ง `TEAM` ให้ตรงกัน มันส่ง `field/soil` `field/tank` ทุก 5 วิ ดินแห้งลงเองวินาทีละ 0.4 % ถ้าปั๊มเดินดินชื้นขึ้นวินาทีละ 2 % และน้ำในถังลดวินาทีละ 1 % · มันฟัง `plc/cmd` แล้วตอบ `plc/state` ตามกฎข้อ 4.2 · ใช้คู่กับบอร์ด Gateway (`sf2_06_smart_gateway.py`) หรือแอปของกลุ่มที่อยากดูแปลงโดยตรง

```
python field_sim.py
```

## 7. ประโยคเริ่มต้นสำหรับสั่ง AI (คัดลอกหน้านี้ทั้งหน้าไปวางก่อน แล้วตามด้วยประโยคข้างล่าง)

**ก. หน้าเว็บไฟล์เดียว**
> เขียนหน้าเว็บ dashboard ไฟล์ HTML ไฟล์เดียว ใช้ mqtt.js จาก CDN ต่อ `wss://broker.hivemq.com:8884/mqtt` subscribe `bento-aiot/team05/#` ตามสัญญาข้างบน แสดงการ์ดอุณหภูมิ ความชื้น ดิน ถังน้ำ กราฟอุณหภูมิย้อนหลัง 5 นาที รายการ event ล่าสุด และปุ่ม "รดน้ำ 10 วินาที" ที่ส่ง `{"cmd":"pump","on":1,"sec":10}` ไป `bento-aiot/team05/cmd` ใช้ client id สุ่ม รองรับค่า null และคีย์ที่ขาดหาย ใช้ textContent ห้ามใช้ innerHTML กับข้อมูลที่รับมา ภาษาไทยทั้งหน้า ใช้บนมือถือได้

**ข. Python จดข้อมูลและเตือน**
> เขียนโปรแกรม Python 3 ใช้ paho-mqtt (รองรับทั้งรุ่น 1.x และ 2.x) ต่อ `broker.hivemq.com` พอร์ต 1883 subscribe telemetry และ event ของ `team05` ตามสัญญาข้างบน จดทุกข้อความลงไฟล์ CSV ที่เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน (utf-8-sig) และเตือนบนจอพร้อมเสียงเมื่อได้ event ที่ `level` เป็น 2 หรือเมื่อ `soil` ต่ำกว่า 30 · ถ้าดินแห้งให้ส่งคำสั่งรดน้ำ แต่เว้นอย่างน้อย 60 วินาทีก่อนสั่งซ้ำ และไม่สั่งเมื่อ `pump` เป็น 1 อยู่แล้ว

**ค. Streamlit**
> เขียนแอป Streamlit หนึ่งไฟล์ ใช้ paho-mqtt ใน thread แยกรับ `bento-aiot/team05/telemetry` ตามสัญญาข้างบน เก็บค่าล่าสุด 300 ใบ แสดงตัวเลขล่าสุดด้วย st.metric กราฟ temp_c และ soil ด้วย st.line_chart รีเฟรชทุก 2 วินาที และปุ่มส่งคำสั่งเปิด/ปิดปั๊มไป `bento-aiot/team05/cmd`

**ง. Node-RED**
> อธิบายทีละขั้นให้สร้าง flow ใน Node-RED ที่ใช้ mqtt in ต่อ `broker.hivemq.com:1883` topic `bento-aiot/team05/telemetry` แปลง JSON แล้วแสดง gauge ความชื้นดินและกราฟอุณหภูมิบน Dashboard พร้อมปุ่มที่ส่ง `{"cmd":"pump","on":1,"sec":10}` ผ่าน mqtt out ไป `bento-aiot/team05/cmd` ตามสัญญาข้างบน และให้ไฟล์ flow JSON ที่ import ได้

**จ. แอปแจ้งเตือนเมื่อ AI พบความผิดปกติ**
> เขียนหน้าเว็บไฟล์เดียว ใช้ mqtt.js จาก CDN ต่อ `wss://broker.hivemq.com:8884/mqtt` subscribe `bento-aiot/team05/ai` ตามสัญญาข้อ 3.9 แสดงการ์ดใหญ่ชื่อโมเดล ป้ายล่าสุด และความมั่นใจ % พร้อมกราฟ conf ย้อนหลัง 2 นาที เตือนด้วยเสียงและ Notification เมื่อ `label` เป็น `anomaly` หรือ `shaking` และ `conf` ตั้งแต่ 60 ขึ้นไป แต่เตือนซ้ำไม่ถี่กว่า 30 วินาที และขึ้น "AI เงียบ" สีเทาเมื่อไม่ได้ยินเกิน 6 วินาที ใช้ textContent ห้ามใช้ innerHTML กับข้อมูลที่รับมา ภาษาไทยทั้งหน้า ใช้บนมือถือได้

เปลี่ยน `team05` เป็นเลขกลุ่มของคุณทุกที่ ทดสอบกับ `fake_board.py` ก่อน แล้วค่อยต่อบอร์ดจริง
