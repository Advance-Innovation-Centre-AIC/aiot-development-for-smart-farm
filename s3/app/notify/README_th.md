# แจ้งเตือนฟาร์มเข้ามือถือ — หน้าเว็บ `notify/` (ntfy · Telegram)

หน้าเว็บไฟล์เดียวที่ฟัง MQTT ของกลุ่ม แล้วส่งแจ้งเตือนเข้ามือถือผ่านแอป **ntfy** (และ Telegram ถ้าตั้งไว้) **ไม่ต้องติดตั้ง Python ไม่ต้องใช้บรรทัดคำสั่ง**
ใช้ได้กับไฟล์บอร์ด S2 (`sf2_02` `sf2_03` `sf2_04` `sf2_06`) และ S3 (`sf3_06` ส่งผล AI · `sf3_08` ภารกิจ AI ในฟาร์ม 7 ภารกิจ)

ทุกหัวข้อ ทุกคีย์ JSON ตรงกับสัญญาตัวจริง [`s2/app/MQTT_CONTRACT_th.md`](../../../s2/app/MQTT_CONTRACT_th.md) (ข้อ 3.3–3.11)

## 2. ตั้งค่าครั้งแรก (ราว 5 นาที)

1. ติดตั้งแอป **ntfy** บนมือถือ (Google Play / App Store)
2. ในหน้าเว็บ ใส่เลขกลุ่ม แล้วกด **สุ่มชื่อใหม่** ได้ชื่อหัวข้อ ntfy ที่ยาวและเดายาก — ชื่อนี้ **คือรหัสผ่าน** ใครรู้ชื่อก็อ่านแจ้งเตือนของกลุ่มได้
3. ในแอป ntfy กด **+** แล้ววางชื่อหัวข้อ (server ใช้ ntfy.sh ตามเดิม) กด Subscribe · หรือเปิด "ลิงก์ subscribe" ที่หน้าเว็บแสดงบนมือถือ · ส่งชื่อหัวข้อไปมือถือตัวเองทางแชตส่วนตัวเท่านั้น
4. กด **ส่งทดสอบ** — ต้องเด้งบนมือถือภายในไม่กี่วินาที (iPhone: อนุญาตแจ้งเตือนของแอป ntfy ในการตั้งค่าของเครื่องด้วย)
5. กด **เริ่มส่งแจ้งเตือน** ป้ายสถานะมุมบนต้องขึ้น "ต่อแล้ว"

ค่าที่ตั้งเก็บในเบราว์เซอร์ของเครื่องนั้น เปิดครั้งหน้าไม่ต้องตั้งใหม่ · **broker ต้องตรงกับ `BROKER` บนบอร์ด** (HiveMQ เป็นค่าเริ่มต้น เลือก Mosquitto เมื่อผู้สอนประกาศ)

## 3. เตือนเรื่องอะไรบ้าง

ตัวเลขท้ายแถวคือความสำคัญของ ntfy: 5 ด่วนที่สุด (มือถือดังนานและเด้งทับจอ) · 4 สูง · 3 ปกติ · 2 ต่ำ (เงียบ ๆ)

### 3.1 จากไฟล์บอร์ด S2 (หัวข้อ `event` และ `telemetry`)

| มาจากหัวข้อ | เตือนเมื่อ | ความสำคัญ |
|---|---|---|
| `event` | กดปุ่มเรียก SW6 · PLC หลุด · Gateway รดน้ำเอง | 4 · 5 · 2 |
| | ปั๊มไม่ยอมเปิดเพราะถังต่ำ (`blocked_tank`) · ติ๊ก "เด้งทุกครั้งที่ปั๊มเปิด/ปิด" ได้ทุกครั้ง | 4 (อื่น ๆ 2) |
| | พืชเริ่มเครียด · แย่แล้ว · กลับมาปกติ (`sf2_04`) | 3 · 5 · 2 |
| | event อื่นของกลุ่ม เช่น `too_hot` | 3 |
| `telemetry` (ติ๊กเปิดก่อน) | ดินแห้ง · ถังใกล้หมด · ร้อนเกิน — เตือนตอนเพิ่งข้ามเกณฑ์ แล้วรอจนกลับมาปกติก่อนเตือนใหม่ | 3 · 4 · 4 |
| | บอร์ดเงียบ (ค่าเริ่มต้น 60 วินาที) · บอร์ดกลับมาแล้ว | 4 · 2 |

### 3.2 ภารกิจ AI ในฟาร์ม (`sf3_08` สัญญาข้อ 3.11) — หนึ่งเหตุการณ์ = แจ้งเตือนหนึ่งใบ

`sf3_08` ตัดสินสองทาง คือ **กฎที่เขียนเอง** (เช่น ค่าสั่นเกินเกณฑ์) กับ **AI** แล้วบอกเองว่าทั้งสองเห็นตรงกันไหม (`agree` `lvl`) และกำลังเตือนอยู่หรือไม่ (`alarm`)
หน้านี้จึง **เชื่อบอร์ดก่อน** ไม่นับ 3 ใน 5 เองซ้ำ มือถือจะไม่เด้งรัวหลายใบต่อเหตุการณ์เดียว

1. **เริ่มเหตุการณ์:** แจ้งหนึ่งใบจาก event `ai_alarm_start` — ยืนยันสองทาง (`lvl` 2) ความสำคัญ 5 · อย่างอื่น 4 ตัวอย่างบนมือถือ:

   > **หมอปั๊มน้ำ: สั่นผิดปกติ**
   > สั่นผิดปกติ · ยืนยันสองทาง: AI 91 % + ค่าสั่น 2.31 > 1.5 m/s² · team05

2. **ระหว่างเหตุการณ์:** บอร์ดส่ง `alarm` = 1 ทุก 2 วินาที หน้านี้ไม่เด้งซ้ำ
3. **ถ้า event หาย:** เห็น `alarm` เปลี่ยนเป็น 1 แต่ไม่มี `ai_alarm_start` ภายใน 3 วินาที (เปิดหน้ากลางทาง หรือ event หายระหว่างทาง) จึงเตือนจาก `alarm` แทน — ยังเป็นใบเดียว (3 วินาทีแก้ได้ในหน้าเว็บ)
4. **จบเหตุการณ์:** แจ้งหนึ่งใบจาก event `ai_alarm_end` ความสำคัญ 2 — `by` = `ack` ขึ้น "รับทราบแล้ว" (มีคนกด SW6 หรือส่ง `ack`) · `clear` ขึ้น "กลับมาปกติ" (เหตุหายไปเอง)

ดังนั้นหนึ่งเหตุการณ์ = แจ้งตอนเริ่มหนึ่งใบ + ตอนจบหนึ่งใบ

**เห็นฝ่ายเดียว (`lvl` 1):** AI เห็นแต่กฎยังไม่ถึง หรือกฎถึงแต่ AI ยังไม่เห็น ยังไม่ใช่เหตุจริง แต่ควรมีคนไปดู หน้านี้แจ้งเบา ๆ (ความสำคัญ 3) หนึ่งใบต่อรอบ:
"AI สงสัย กฎยังไม่เห็น" หรือ "กฎเห็น AI ยังไม่เห็น" · ปิดได้ในหน้าเว็บ (ข้อ 4)

| `m` | ชื่อในแจ้งเตือน | ป้ายที่เป็นเหตุ (ความหมาย) | ค่าของกฎที่บอกในแจ้งเตือน (`rk`) |
|---|---|---|---|
| `pump` | หมอปั๊มน้ำ | `anomaly` สั่นผิดปกติ | `vib` ค่าสั่น m/s² |
| `siren` | ยามฟังไซเรน | `sirens` เสียงไซเรน | `loud` ดังต่อเนื่องกี่วินาที |
| `barn` | หูโรงเรือน | `cough` เสียงไอ · `water_tap` ก๊อกน้ำเปิดทิ้ง · `baby_cry` เด็กร้อง | `rate` ครั้ง/10 นาที · `dur` ค้างอยู่กี่วินาที |
| `night` | ยามกลางคืน | `chainsaw` เลื่อยยนต์ · `crackling_fire` ไฟไหม้ · `dog` สุนัขเห่า | `loud` ดังต่อเนื่องกี่วินาที |
| `voice` | สั่งปั๊มด้วยเสียง | `go` สั่งเปิดปั๊ม · `stop` สั่งปิดปั๊ม | `btn` คนกดยืนยันแล้วหรือยัง |
| `worker` | คนงานปลอดภัย | `sitting` `standing` (นิ่ง) | `dur` ไม่ขยับกี่วินาที |
| `drill` | ช่างซ่อมโรงเรือน | `wood_out` `plastic_out` | `loud` สว่านเดินกี่วินาที |

**event อื่นของภารกิจ:**

| event | แจ้งเตือน | ความสำคัญ |
|---|---|---|
| `rain` | ฝนตก งดรดน้ำได้ | 2 |
| `voice_cmd` ที่ `ok` = 0 | ไม่ทำตามคำสั่งเสียง (ยังไม่ยืนยัน / สั่งถี่เกิน 3 วิ) | 3 |
| `voice_cmd` ที่ `ok` = 1 | ทำตามคำสั่งเสียง — ปิดไว้เป็นค่าเริ่มต้น เปิดได้ในหน้าเว็บ | 2 |
| `check_in` ที่ `ok` = 0 | คนงานไม่ตอบ! — นับเป็นใบเริ่มเหตุการณ์ `ai_alarm_start` ที่ตามมาจึงไม่เด้งซ้ำ | 5 |
| `check_in` ที่ `ok` = 1 | ไม่แจ้ง (คนงานกด SW6 ว่าโอเค) | — |
| `drill_done` | เจาะเสร็จ — ปิดไว้เป็นค่าเริ่มต้น เปิดได้ในหน้าเว็บ | 2 |

- model `"rule-only"` ป้าย `"-"` = ภารกิจที่ไม่มีโมเดล (ใช้กฎอย่างเดียว) ยังทำงานอยู่ ไม่ใช่หยุด · model `""` ป้าย `"-"` = หยุดโมเดลอยู่ ไม่นับ
- แตะแจ้งเตือนแล้วเปิดหน้า `ai_farm.html` ของกลุ่ม (`s3/app/ai_farm.html?team=team05`) ลิงก์คิดจากที่อยู่ของหน้านี้เอง เปิดหน้านี้จาก GitHub Pages ลิงก์จึงใช้บนมือถือได้

### 3.3 บอร์ดที่ไม่ส่ง `alarm` (`sf3_06` สัญญาข้อ 3.9) — หน้านี้นับเอง

| เตือนเมื่อ | ความสำคัญ |
|---|---|
| ป้ายอันตรายอย่างน้อย 3 ใน 5 ผลล่าสุด → "AI พบความผิดปกติ" | 5 |
| หลังเตือนแล้ว นับได้ต่ำกว่าเกณฑ์ติดกันครบ 5 ผล → "AI กลับมาปกติ" | 2 |

- ป้ายอันตรายค่าเริ่มต้น `anomaly, shaking, sirens, cough, baby_cry, chainsaw, crackling_fire, alarm` (ชุดเดียวกับ `sf3_04` `sf3_06`) แก้ได้ในหน้าเว็บ
- ระหว่างเขย่า ป้ายสลับ `anomaly` ↔ `unlabeled` ทุก 1–2 วินาที จึงนับ 3 ใน 5 ไม่ใช่เตือนทุกครั้งที่เห็นป้ายเดียว และ "กลับมาปกติ" ต้องรอให้ต่ำกว่าเกณฑ์ติดกันครบ 5 ผล ไม่อย่างนั้นจะเด้งสลับ "พบ / กลับมาปกติ" ทุกไม่กี่วินาที
- ผลที่ `model` ว่าง (หยุดโมเดลอยู่) หรือป้าย `"-"` (ยังไม่มีผล) ไม่นับ

### 3.4 ใช้กับบอร์ด AI ทุกแบบ

- **AI เงียบ** (ความสำคัญ 4): ไม่ได้ยินหัวข้อ `ai` เกิน 6 วินาที นับหลังได้ยินผลแรกแล้วเท่านั้น ได้ยินใหม่จึงเตือนได้อีก
- ตัวเลขและชื่อป้ายทุกตัวแก้ได้ในหน้าเว็บ (ข้อ 4) · เว้นช่องเกณฑ์ว่าง = ไม่ใช้กฎนั้น
- **กันสแปม:** เรื่องเดิมเด้งซ้ำได้เมื่อพ้นช่วงเว้น (ค่าเริ่มต้น 120 วินาที) และรวมกันไม่เกินเพดานต่อชั่วโมง (ค่าเริ่มต้น 30) เพราะ ntfy.sh ให้ส่งได้ราววันละ 250 ข้อความต่อผู้ส่ง ห้องเรียนที่ใช้เน็ตเดียวกันจึงใช้โควตาร่วมกัน · ที่พักไว้ขึ้นในตัวนับ และบอกในข้อความถัดไปของเรื่องนั้น

## 4. ทดสอบโดยไม่มีบอร์ด

- ติ๊ก **ลองเฉย ๆ (dry-run)** หน้าเว็บเขียนลงบันทึกว่าจะส่งอะไร ไม่ส่งไป ntfy หรือ Telegram จริง
- **คาบ 2:** บอร์ดจำลองตามสัญญาข้อ 6 (เปิด [`s2/app/fake_board.html`](../../../s2/app/fake_board.html) กด เริ่ม) ด้วยเลขกลุ่มเดียวกัน: จะเห็น "มีคนกดเรียกที่ฟาร์ม" และ "พืชแย่แล้ว" (ติ๊กเตือนจาก telemetry ด้วย จะเห็น "ดินแห้ง")
- **คาบ 3:** บอร์ดจำลองในหน้า `ai_farm.html` ของกลุ่ม หรือรัน `sf3_06` / `sf3_08` ใน BENTO Emulator (สัญญาข้อ 6) แล้วดูว่าหนึ่งเหตุการณ์ได้แจ้งเตือนหนึ่งใบจริง
- ใช้เลขกลุ่มที่ไม่มีใครใช้ (เช่น `team99`) และอย่าเปิดตัวจำลองพร้อมบอร์ดจริงที่ใช้เลขกลุ่มเดียวกัน

## 5. Telegram (ไม่บังคับ)

ใส่ bot token (จาก @BotFather) และ chat id ในหน้าเว็บ แล้วทุกแจ้งเตือนจะส่งเข้า Telegram พร้อม ntfy

- token **ไม่ถูกจำไว้** เว้นแต่ติ๊ก "จำไว้ในเบราว์เซอร์นี้" — ติ๊กเฉพาะเครื่องส่วนตัว
- token คือกุญแจของบอท ห้ามวางในแชตกลุ่มหรือในไฟล์ · หน้าเว็บไม่แสดง token ในบันทึก

## 6. ข้อจำกัดที่ต้องรู้

- หน้าเว็บนี้คือ "ตัวส่ง" ต้อง **เปิดค้างไว้บนเครื่องที่ต่อเน็ต** ปิดแท็บ ปิดเครื่อง หรือเครื่องหลับเมื่อไร แจ้งเตือนก็หยุด
- ดีที่สุดคือโน้ตบุ๊กเสียบปลั๊ก ตั้งไม่ให้เครื่องหลับ แท็บนี้อยู่เบื้องหลังได้
- บนมือถือ ถ้าสลับแอปหรือจอดับ เบราว์เซอร์จะพักหน้านี้ — เปิดไว้หน้าสุด เสียบสายชาร์จ และติ๊ก **กันหน้าจอดับ** (ถ้าเบราว์เซอร์ไม่รองรับ หน้าเว็บจะบอก)
- มือถือที่ **รับ** แจ้งเตือนผ่านแอป ntfy ไม่ต้องเปิดหน้านี้
- กลุ่มหนึ่งเปิดหน้านี้เครื่องเดียวพอ เปิดสองเครื่องด้วยหัวข้อเดียวกัน มือถือจะเด้งซ้ำสองครั้ง
- "แจ้งเตือนบนเครื่องนี้" เป็นช่องทางเสริม ใช้ได้ดีบนโน้ตบุ๊ก · มือถือ Android ส่วนใหญ่ไม่ขึ้นแจ้งเตือนจากหน้าแบบนี้ ใช้แอป ntfy เป็นหลัก

## 7. ความเป็นส่วนตัวและความปลอดภัย

- broker สาธารณะและ ntfy.sh **ใครก็อ่านได้** ถ้ารู้ชื่อหัวข้อ — ห้ามส่งชื่อคน เบอร์โทร ที่อยู่ หรือรหัสผ่านใด ๆ
- ชื่อหัวข้อ ntfy คือรหัสผ่านของแจ้งเตือนกลุ่ม ถ้าหลุด กด **สุ่มชื่อใหม่** แล้ว subscribe ชื่อใหม่ในแอป
- หน้าเว็บฟังเฉพาะหัวข้อของกลุ่มตัวเอง และแสดงข้อความที่รับมาด้วย `textContent` เสมอ ใครส่งอะไรมาก็ไม่ถูกรันเป็นโค้ด
