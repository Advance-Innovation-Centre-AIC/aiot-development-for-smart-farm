3. ตาราง holding register ช่องละ 16 บิต · เลขช่องเริ่มที่ 0

ช่องชื่อค่าฐานสิบหกสิทธิ์ความหมาย
HR0ปั๊ม----อ่าน/เขียน0 = ดับ · 1 = เดิน · เขียนได้แค่ 0 หรือ 1
HR1ดิน %----อ่านอย่างเดียวปัดเป็นจำนวนเต็ม
HR2ถัง %----อ่านอย่างเดียวปัดลงเสมอ (9.9 เป็น 9 ตรงกับที่ระบบป้องกันเห็นว่า "ต่ำกว่า 10")
HR3ปั๊มเหลือกี่วิ----อ่านอย่างเดียว0 = ปั๊มดับอยู่
HR4เหตุปฏิเสธล่าสุด----อ่านอย่างเดียว0 ไม่มี · 1 ถังต่ำกว่าเกณฑ์ · 2 ค่าที่เขียนผิด

ข้อยกเว้นที่ PLC ตอบ: 01 ไม่รู้จักคำสั่ง · 02 ไม่มี register ให้ทำแบบนั้น (เช่นเขียน HR1–HR4) · 03 ค่าไม่ถูกต้อง (เช่นเขียน HR0 = 2) · 04 ไม่ยอมทำ (ระบบป้องกัน: ถังต่ำ)

ทำไมหน้าเว็บไม่ต่อ PLC ตัวจริง

เบราว์เซอร์ เปิดการเชื่อมต่อ TCP ตรงไปหา PLC ที่พอร์ต 502 ไม่ได้ หน้าเว็บคุยออกไปได้แค่ HTTP และ WebSocket (MQTT ของหน้านี้ก็วิ่งบน WebSocket) จึงต้องมี PLC จำลองอยู่ในหน้านี้เอง

ถ้าจะต่อ PLC ตัวจริง ต้องมีโปรแกรมเกตเวย์ MQTT ↔ Modbus TCP รันอยู่บน เครื่องของผู้สอน ที่อยู่ในวงแลนเดียวกับ PLC · ผู้เรียนไม่ต้องใช้เกตเวย์นั้น ทุกขั้นของบทเรียนนี้ทำงานบนหน้านี้กับบอร์ด (หรือ BENTO Emulator)

PLC (Modbus TCP)

วิธีใช้กับ cp3_06_modbus_frame.py

  1. ใส่เลขกลุ่ม (หรือเปิดลิงก์ที่มี ?team=team05) แล้วกด เริ่ม · เปิดหน้านี้ค้างไว้ อยู่แท็บหลังได้ · เปิดหน้าเดียวต่อกลุ่ม
  2. ใน cp3_06_modbus_frame.py ตั้ง WIFI_SSID WIFI_PASS และ TEAM ให้ตรงกับหน้านี้ แล้วรันบนบอร์ดหรือ BENTO Emulator
  3. กด SW5 = FC03 อ่าน HR0–HR2 · กด SW6 = FC06 สลับปั๊ม → 12 ไบต์บนจอบอร์ดคือกรอบ "ขาไป" ในข้อ 4 ทุกไบต์ · คำตอบกลับถึงบอร์ด = "ยืนยันแล้ว"
  4. กด ถอดสาย PLC แล้วกด SW6 → บอร์ดขึ้น plc_offline และสถานะปั๊มเป็น -- (ไม่รู้ ไม่เดาว่าสำเร็จ)
  5. ใส่น้ำในถัง 5 กด เปิด PLC ใหม่ แล้วกด SW6 สั่งเปิด → บอร์ดขึ้น "PLC ปฏิเสธ 4" (ระบบป้องกันถังแห้ง)
สัญญา MQTT ของบทนี้ (ตายตัว ตรงกับที่บอร์ดใช้)

ขอ .../modbus/req {"n":7,"fc":3,"addr":0,"qty":3,"hex":"000700000006010300000003"} · มี hex = ส่งกรอบนั้นทุกไบต์ตามที่บอร์ดวาด · ไม่มี = สร้างกรอบให้จาก fc / addr / qty หรือ value

ตอบ .../modbus/resp {"n":7,"ok":1,"hex":"<กรอบคำตอบ>","v":[0,45,80]} · PLC ปฏิเสธ {"n":8,"ok":0,"hex":"...","exc":4} · เกตเวย์ปฏิเสธ {"n":8,"ok":0,"err":"..."}

  • bad_req อ่าน JSON ไม่ได้หรือช่องไม่ครบ (n เป็น null ถ้าอ่านไม่ได้) · bad_frame กรอบผิดรูป ไม่ส่งต่อ
  • too_big ขออ่านเกิน 10 ช่อง (คำตอบจะล้นกล่องรับของบอร์ด) · plc_offline ต่อ PLC ไม่ได้ · bad_reply PLC ตอบผิดรูป
  • n ของคำตอบ = n ของคำขอ ใช้จับคู่ · ok = 1 เฉพาะเมื่อ PLC ยืนยันแล้วเท่านั้น
